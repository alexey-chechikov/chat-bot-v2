# 29–31 октября: исправление модели сетки и вход из 3–5 ордеров с общим стопом

Дата исследования: 02.11.2026. Живая торговля, настройки и процессы не изменялись. Все цены — исторический BTCUSDT perpetual Bybit; суммы — модельные USDT. Время в таблицах UTC; для Польши 29–31 октября прибавить 1 час.

**Ответ пользователю:** вход из 3–5 заранее ограниченных ордеров с общим стопом и тейком стоит рассматривать как отдельную гипотезу. Он позволяет определить размер риска до сделки, прекратить набор и закрыть весь цикл без восстановления сетки. В этой проверке нашлись положительные исторические примеры, но ни один из 72 вариантов не был положителен одновременно на обучении и проверке. Прибыльный пример не превращён в подтверждённую стратегию.

**Важное исправление предыдущего отчёта:** три октябрьских LONG были ошибочно смоделированы как maker-исполнения по старым уровням выше рынка. Это дефект модели исполнения и повторного разрешения сетки. Старые −8,7744 USDT по этим лотам и итог +1,2418 USDT по контрольному S02506 нельзя использовать как корректную оценку реально исполнимой стратегии. Их исторический журнал сохранён для аудита; здесь объяснена ошибка. Предыдущие 6 912 сочетаний массово заново не оптимизировались. Новый расчёт корзин использует отдельный исполнитель.

### Конкретная ошибка исполнения

В 30.10 04:00 рынок открывается 78 187,3, максимум часа 78 420,0. Старая модель тем не менее начислила три maker-покупки 79 307,2 / 79 750,5 / 80 193,8. Это были **заново разрешённые** заявки, а не давно стоявшие заявки, через которые прошёл ценовой гэп.

PostOnly-лимитка, способная немедленно исполниться при постановке, отклоняется; обычная GTC-покупка выше текущего ask становится рыночной по характеру исполнения и не обязана исполняться по заданному худшему лимиту. [Официальное описание Post-Only Bybit](https://www.bybit.com/en/help-center/article/Post-Only-Order?category=5f2fb74e9c8b771130), [параметры приказов API](https://bybit-exchange.github.io/docs/v5/order/create-order).

Только для этих трёх лотов:

| Трактовка | Итог до конца периода |
|---|---:|
| Старый ошибочный maker-расчёт | −8,7744 |
| Отменить некорректное повторное разрешение / отклонить PostOnly | 0,0000 по этим заявкам |
| Иллюстративно исполнить GTC по open+0,02%, taker, с исходными запрошенными BTC-количествами | −3,0522 |

Последняя строка — чувствительность к модели исполнения, а не восстановление настоящего стакана. Нельзя просто прибавить 8,7744 к старому общему итогу и объявить исправленную доходность: отсутствие остатка изменит доступность следующих входов. Нужен полный повтор уже исправленного исполнителя. В этой сессии вместо повторного выбора сетки исследована новая конечная корзина по просьбе пользователя.

Моя интерпретация: на 00:00 нет подтверждённого восстановления диапазона для LONG. Цена пробила его низ, агрессивный поток направлен вниз, OI растёт. Это совместимо с усилением активности на снижении, но не устанавливает состав открытых позиций. Accounts>1 означает больше long-аккаунтов по счётчику, не больший денежный объём и не позицию китов. Отскок+0,30% к 04:00 не возвращает цену ни в старый канал, ни над средние.

Пользователь предложил вход частями с понятным стопом/тейком; конкретную оценку этих октябрьских баров пользователь пока не высказывал. Эта интерпретация принадлежит Codex. Ряды: Delta6 — taker-поток Binance за 6 часов, OI/accounts — Bybit с задержкой доступности 1 час; это не CoinGlass Whale Index, не лимитный стакан и не агрегированные ликвидации. Подробнее о единицах: [Bybit OI](https://bybit-exchange.github.io/docs/v5/market/open-interest), [accounts](https://bybit-exchange.github.io/docs/v5/market/long-short-ratio).

## 3. Конечная корзина: проверенные правила

Вместо бесконечного восстановления уровней проверены два способа набора:

- **Pullback:** первый ордер рынком после завершённого сигнала, остальные 2 или 4 — лимитками на откате против направления позиции. Последний отстоит от первого на 0,75 ATR; промежуточные распределены равномерно.
- **Pyramid:** первый ордер рынком, остальные 2 или 4 — stop-market при движении в пользу позиции, на той же дистанции 0,75 ATR. Это добавление по подтверждению, не усреднение убытка.

Также посчитан один ордер для сравнения. Общий плановый риск всей корзины **до 3 USDT**, суммарный плановый номинал **до 300 USDT** при условной базе 1 000 USDT. Это не риск 3 USDT на каждый ордер и не 3–5 ордеров по 100 USDT автоматически. Риск включает предполагаемые комиссии и проскальзывание на стопе; гэп и будущий funding могут превысить эту оценку. Размер позиции уменьшается под стоп, стоп не приближается ради нужного размера.

### Стоп и тейк

| Параметр | Проверенные варианты |
|---|---|
| Контекст | H4; H1 с предыдущим закрытым H4 |
| Сигнал | Прежний фиксированный канал S02506: подтверждение 2 свечи, цена по нужную сторону EMA, вне формального диапазона |
| Количество | 1 /3 /5, одинаковый лимит планового риска |
| Стоп ATR | Signal close ±1,5 ATR, против позиции |
| Стоп структуры | Для SHORT максимум последних 6 закрытых сигнальных свечей +0,25 ATR; для LONG минимум −0,25 ATR |
| Тейк | Противоположная граница DC30; либо 1,5R; либо 2R |
| Срок незаполненных заявок | 3 свечи сигнального ТФ; также отменяются при противоположном риске |
| Срок всей позиции | 20 свечей:80 часов H4 или 20 часов H1+H4 |
| Завершение | Общий стоп /общий TP /срок /конец расчёта закрывает остаток и отменяет всё незаполненное |
| Следующий вход | Новый сигнал, отсутствие старой корзины и пауза 2 сигнальные свечи; без автоматического переворота |

R-цель — расстояние от **плановой средней полного набора** до фиксированного стопа. Если заполнился только первый ордер, фактическое соотношение прибыли к риску отличается. Цель после частичного исполнения не переносится. Это осознанная проверенная трактовка, а не универсальное правило. В варианте `channel` цель одинакова для 1/3/5 ордеров на одном сигнале; в R-вариантах она меняется вместе с плановой средней.

Перед активацией проверяется: стоп лежит с правильной стороны всех входов, цель — дальше всех плановых входов по направлению сделки, цены положительны. Гэп за стоп /цель или неверное положение дополнительных уровней отменяют план. Старую нарушенную сетку эта схема не запускает: входная корзина получает новый сигнал, собственные цены и фиксированный стоп.

Для будущего контроллера диапазона отдельно сформулирован запрет повторного разрешения: пробой замороженной границы закрывает текущий эпизод и отменяет незаполненные заявки; новое разрешение требует нового setup и нового канала с ценой внутри него. Нельзя снять запрет только потому, что подвижная граница успела догнать цену. Эта поправка описана, но не выдаётся за уже проверенное улучшение всех старых сеток.

В примере B018 отдельные количества около 0,00051 BTC меньше этого минимума. **С бюджетом риска 3 USDT точный такой план на Bybit не исполним.** Если насильно округлить каждую часть до 0,001 BTC, три ордера потребуют номинала 240,33 USDT и планового риска 5,9061, пять —400,56 USDT и 9,8158. Пять также превысят заданный номинальный предел 300. Корректная реакция контроллера — пропустить план или уменьшить число частей, а не молча поднять риск.

Спецификация WEEX отличается: в официальной документации отдельно заданы минимальный размер и точность; пример документации не является актуальным лимитом конкретного аккаунта. Текущий публичный ответ WEEX в этой проверке не получен. Поэтому исполнимость округлённых 3/5 частей на WEEX и результат на его ценах пока **не проверены**. [Описание рыночной спецификации WEEX](https://www.weex.io/api-doc/catalog/core-trading-futures/api/rest-api).

Стоп после срабатывания должен уменьшать имеющуюся позицию, а не открывать обратную; незаполненные входы отменяются вместе с закрытием. Триггер стопа, тип цены, округление, reduce-only и гонка исполнения/отмены должны отдельно проверяться в контроллере биржи. Никаких реальных заявок здесь не размещалось.

## 7. Как считалось исполнение

Первый вход — следующий H1 open после закрытого сигнала; H4 подтверждается только в своей границе. Для H1+H4 используется предыдущий завершённый H4, известный на открытии H1, как в прежней причинной реконструкции.

Дополнительные pullback — однократные пассивные лимитки; pyramid — stop-market. Комиссии-**допущения**: maker0,016%, taker0,048%; market slippage0,02% на сторону; для лимитки требуется проход 0,01%. Это не утверждение о действующих тарифах аккаунта. В стресс-тесте комиссия и market slippage удвоены без намеренного уменьшения размеров под выросшие расходы.

Для каждого H1 сравниваются два пути O-H-L-C и O-L-H-C. Берётся менее выгодная переоценка на конце этого бара. Это локальная неблагоприятная условность, не наблюдавшийся путь и не математическая гарантия самого плохого результата всей истории. При добавлении лимитного лота TP этой корзины в том же баре не разрешается; общий стоп действует сразу. Для выбранных представителей контрольные результаты совпали на двух фиксированных путях. Пропуски исполнения, очередь и частичные объёмы рынка не восстановлены.

При гэпе через общий стоп исполнение ухудшается до open с проскальзыванием. Переносимые лимитки на пути такого неблагоприятного гэпа могут добраться прежде стопа в принятой модели. Funding начисляется переносимому остатку до приказов в момент расчёта по сохранённой mark-цене. Поэтому фактический модельный убыток цикла может быть больше плановых 3 USDT: например, B018 за всю историю имеет максимум 3,0433. «Понятный стоп» не равен гарантированной сумме убытка.

R-TP, стоп и набор конечны: никаких доливок сверх 3/5, расширения стопа, скрытого мартингейла или восстановления закрытых ордеров. В конце периода всё закрыто, комиссии и funding входят в ledger. Просадка — по часовым закрытиям, не максимальная тиковая.

"""One-shot 1/3/5-order baskets, isolated offline research. No bot imports.
Fixed stop/TP, no refill, cap by planned stop loss including fees/slippage.
OHLC path uncertainty is explicit; this is not a tick execution reconstruction.
"""
from pathlib import Path
import sys,json,copy
import numpy as np
import pandas as pd
P=Path(__file__).resolve().parent;OLD=P.parent/'strategy432_regimes_20261102'
sys.path.insert(0,str(OLD))
from features import signals,candles
from engine import Replay
BASE=json.loads((OLD/'selection_frozen.json').read_text())['selected'][3]['config']
FEE_M=.00016;FEE_T=.00048;SLIP=.0002;THROUGH=.0001

def inputs(context):
    f=pd.read_parquet(OLD/f'features_{context}.parquet').copy()
    s=signals(f,dict(BASE,context=context))
    f['long']=s.long;f['short']=s.short;f['cut_long']=s.cut_long;f['cut_short']=s.cut_short
    # Include the just-closed signal bar; never an unconfirmed swing pivot.
    f['swing_lo']=f.low.rolling(6).min();f['swing_hi']=f.high.rolling(6).max()
    return f

def fill(c,k,raw,time,market,mult):
    order=c['orders'][k]
    if order['status']!='pending':return
    side=c['side'];price=raw*(1+side*SLIP*mult) if market else raw
    fee=order['qty']*price*(FEE_T if market else FEE_M)*mult
    order.update(status='filled',fill=price,entry_time=str(time),entry_fee=fee,funding=0.)
    c['cash']-=fee;c['fees']+=fee
    c['events'].append(dict(time=str(time),event='fill',order=k+1,price=price,qty=order['qty']))

def stop_out(c,raw,time,reason,mult,market=True):
    if c['closed']:return
    side=c['side'];px=raw*(1-side*SLIP*mult) if market else raw
    for k,o in enumerate(c['orders']):
        if o['status']=='filled':
            gross=side*o['qty']*(px-o['fill']);fee=o['qty']*px*(FEE_T if market else FEE_M)*mult
            c['cash']+=gross-fee;c['fees']+=fee;c['gross']+=gross
            o.update(status='closed',exit=px,exit_time=str(time),exit_fee=fee,net=gross-o['entry_fee']-fee+o['funding'])
        elif o['status']=='pending':o['status']='cancelled'
    c.update(closed=True,reason=reason,exit_time=str(time))
    c['events'].append(dict(time=str(time),event=reason,price=px))

def cancel_pending(c,time,reason):
    n=0
    for o in c['orders']:
        if o['status']=='pending':o['status']='cancelled';n+=1
    if n:c['events'].append(dict(time=str(time),event=reason,orders=n))

def mark(c,price):
    return c['cash']+sum(c['side']*o['qty']*(price-o['fill']) for o in c['orders'] if o['status']=='filled')

def make_plan(row,opening,cfg,time,mult=1.):
    side=1 if row['long'] else -1;n=cfg['orders'];atr=float(row['atr'])
    stop=float(row['close']-side*1.5*atr) if cfg['stop']=='atr1.5' else float(row['swing_lo']-.25*atr if side==1 else row['swing_hi']+.25*atr)
    if not np.isfinite(stop) or stop<=0 or side*(opening-stop)<=0:return None,'gap_stop'
    direction=-side if cfg['mode']=='pullback' else side
    prices=opening+direction*np.linspace(0,.75*atr,n)
    expected=np.array([p*(1+side*SLIP) if k==0 or cfg['mode']=='pyramid' else p for k,p in enumerate(prices)])
    if np.any(side*(expected-stop)<=0):return None,'levels_beyond_stop'
    # Equal planned notional per component. 1-order benchmark has same risk cap.
    stop_fill=stop*(1-side*SLIP)
    feein=np.array([FEE_T if k==0 or cfg['mode']=='pyramid' else FEE_M for k in range(n)])
    risk_per_usdt=(side*(expected-stop_fill)+expected*feein+stop_fill*FEE_T)/expected
    nominal=min(300/n,3/risk_per_usdt.sum());qty=nominal/expected
    avg=float((expected*qty).sum()/qty.sum())
    if cfg['target']=='channel':target=float(row['hi'] if side==1 else row['lo'])
    else:target=float(avg+side*float(cfg['target'][1:])*abs(avg-stop))
    if np.any(side*(target-expected)<=0):return None,'target_behind_entry'
    orders=[dict(price=float(p),qty=float(q),status='pending') for p,q in zip(prices,qty)]
    c=dict(side=side,orders=orders,stop=stop,target=target,planned_average=avg,
        planned_risk=float(nominal*risk_per_usdt.sum()),planned_notional=float(nominal*n),
        signal_time=str(row['known_utc']),entry_time=str(time),cash=0.,gross=0.,fees=0.,funding=0.,
        closed=False,events=[],mode=cfg['mode'],context=cfg['context'],ambiguous_bars=0)
    fill(c,0,opening,time,True,mult)
    return c,None

def path_step(original,bar,time,path,mult=1.):
    c=copy.deepcopy(original);side=c['side'];o,h,l,cl=map(float,bar)
    def adverse_cross(price,level):return side*(price-level)<=0
    # Carried resting limits can fill through an adverse gap before the common stop.
    if adverse_cross(o,c['stop']):
        if c['mode']=='pullback':
            for k,order in enumerate(c['orders']):
                if order['status']=='pending' and side*(o-order['price']*(1-side*THROUGH))<=0:fill(c,k,order['price'],time,False,mult)
        stop_out(c,o,time,'stop_gap',mult);return c
    if side*(o-c['target']*(1+side*THROUGH))>=0:
        stop_out(c,c['target'],time,'target_gap',mult,False);return c
    added_limit=False
    # Handle gap across entry trigger; pyramid stop orders pay gap and slippage.
    for k,order in enumerate(c['orders']):
        if order['status']!='pending':continue
        crossed=side*(o-order['price'])>=0 if c['mode']=='pyramid' else side*(o-order['price']*(1-side*THROUGH))<=0
        if crossed:
            market=c['mode']=='pyramid';fill(c,k,o if market else order['price'],time,market,mult)
            added_limit|=not market
    points=[o,h,l,cl] if path=='OHLC' else [o,l,h,cl]
    for start,end in zip(points,points[1:]):
        if c['closed']:break
        up=end>start
        if end==start:continue
        events=[]
        for k,order in enumerate(c['orders']):
            if order['status']!='pending':continue
            level=order['price'] if c['mode']=='pyramid' else order['price']*(1-side*THROUGH)
            entry_up=side==1 if c['mode']=='pyramid' else side==-1
            if up==entry_up:events.append((level,'entry',k))
        if up==(side==-1):events.append((c['stop'],'stop',-1))
        if up==(side==1):events.append((c['target']*(1+side*THROUGH),'target',-1))
        events=[v for v in events if (start<v[0]<=end if up else end<=v[0]<start)]
        events.sort(key=lambda v:v[0],reverse=not up)
        for level,kind,k in events:
            if c['closed']:break
            if kind=='entry':
                order=c['orders'][k];market=c['mode']=='pyramid'
                fill(c,k,order['price'],time,market,mult);added_limit|=not market
            elif kind=='stop':stop_out(c,c['stop'],time,'stop',mult)
            elif not added_limit:stop_out(c,c['target'],time,'target',mult,False)
    return c

def advance(c,bar,time,mult=1.,path='adverse'):
    if path in ('OHLC','OLHC'):return path_step(c,bar,time,path,mult)
    a=path_step(c,bar,time,'OHLC',mult);b=path_step(c,bar,time,'OLHC',mult)
    different=abs(mark(a,bar[3])-mark(b,bar[3]))>1e-10
    result=min([a,b],key=lambda z:mark(z,bar[3]))
    result['ambiguous_bars']+=int(different)
    return result

def run(frame,cfg,start,end,mult=1.,path='adverse',detail=False):
    r=Replay(start,end);decision=frame.set_index('known_utc').reindex(r.known)
    cols=['long','short','cut_long','cut_short','close','atr','swing_lo','swing_hi','lo','hi']
    actions=[]
    for t,v in zip(r.known,decision[cols].itertuples(index=False,name=None)):
        actions.append(None if pd.isna(v[0]) else dict(zip(['known_utc']+cols,[t]+list(v))))
    hours=4 if cfg['context']=='H4' else 1
    active=None;pending=None;net=0.;peak=0.;dd=0.;cool_until=None
    cycles=[];equity=[];rejections={};seq=0
    def finish(c):
        nonlocal net,cool_until
        assert abs(c['cash']-(c['gross']-c['fees']+c['funding']))<1e-8
        assert abs(c['cash']-sum(o.get('net',0) for o in c['orders']))<1e-8
        c['net']=c['cash'];c['filled']=sum(o['status']=='closed' for o in c['orders'])
        net+=c['net'];cycles.append(c);cool_until=seq+2
    for i,(o,h,l,cl) in enumerate(r.rows):
        time=r.ts[i]
        if active:
            rate=r.funding[i]
            for order in active['orders']:
                if order['status']=='filled':
                    payment=-active['side']*order['qty']*r.mark[i]*rate
                    order['funding']+=payment;active['cash']+=payment;active['funding']+=payment
            if (time-pd.Timestamp(active['entry_time'])).total_seconds()>=20*hours*3600:
                stop_out(active,o,time,'time',mult);finish(active);active=None
        if pending is not None:
            if active is None:
                active,reason=make_plan(pending,o,cfg,time,mult)
                if reason:rejections[reason]=rejections.get(reason,0)+1
            pending=None
        if active:
            if (time-pd.Timestamp(active['entry_time'])).total_seconds()>=3*hours*3600:cancel_pending(active,time,'entry_expiry')
            active=advance(active,[o,h,l,cl],time,mult,path)
            if active['closed']:finish(active);active=None
        eq=net+(mark(active,cl) if active else 0.)
        peak=max(peak,eq);dd=max(dd,peak-eq)
        if detail:equity.append(dict(time=str(r.known[i]),pnl=eq,active=bool(active)))
        a=actions[i]
        if a is None:continue
        seq+=1
        if active and (a['cut_long'] if active['side']==1 else a['cut_short']):cancel_pending(active,r.known[i],'directional_risk')
        if active is None and (cool_until is None or seq>=cool_until) and bool(a['long'])!=bool(a['short']):pending=a
    if active:
        stop_out(active,r.rows[-1][3],r.known[-1],'terminal',mult);finish(active)
        dd=max(dd,peak-net)
        if detail:equity.append(dict(time=str(r.known[-1]),pnl=net,active=False))
    metrics=dict(net=net,drawdown=dd,cycles=len(cycles),wins=sum(c['net']>0 for c in cycles),
        orders_filled=sum(c['filled'] for c in cycles),fees=sum(c['fees'] for c in cycles),funding=sum(c['funding'] for c in cycles),
        stops=sum(c['reason'].startswith('stop') for c in cycles),targets=sum(c['reason'].startswith('target') for c in cycles),
        time_exits=sum(c['reason']=='time' for c in cycles),terminal=sum(c['reason']=='terminal' for c in cycles),
        ambiguous_bars=sum(c['ambiguous_bars'] for c in cycles),max_cycle_loss=max([0.]+[-c['net'] for c in cycles]))
    if detail:return metrics,cycles,equity,rejections
    return metrics
