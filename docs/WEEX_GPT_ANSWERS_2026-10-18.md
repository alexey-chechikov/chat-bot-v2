### 2.1 Несколько сеток на одном символе (6912e1c)

**Дефект, который это закрывает.** Сетка считала своими все ордера символа с префиксом `b7g`. `_orphans` усыновлял чужой вход как свой или снимал его как сироту. Вторая сетка на BTCUSDT воровала бы ордера первой. На b3f92ca все 23 новых теста падают именно на этом.

**Решение.**
- `cid_tag` — один знак `[A-Za-z0-9]`; без ключа берётся первая буква символа. У живых BTC (`b7gB…`) и ETH (`b7gE…`) формат не изменился. Новые знаки: 3, 4, 8.
- Своими считаются только ордера с префиксом `b7g` + знак. Это `self.open`, сироты, лишние, эскалации неизвестных.
- Негодный или совпавший знак — `ConfigError`, сетка стоит, ни одного запроса к бирже. Совпали — встают обе.
- `event_id` передачи содержит знак сетки.

**Общая позиция LONG** (хедж-режим):
- `_flatten_side` закрывает только объём своих лотов.
- `_reconcile_side` сознательно не вычитает лоты соседей. Внешнее закрытие части общей позиции не видно, пока её хватает на лоты этой сетки. Правило для оператора: при работающих сетках BTC LONG руками не трогать.
- `account_now` сверяет общую позицию с суммой лотов всех сеток.

**WEEX `/capi/v3/order/history` игнорирует `page`** (проверено на счёте 15.10: страницы 0/1/2/500 вернули те же 100 orderId; окно `startTime/endTime` работает).
- `_find_by_cid` при повторе страницы делит окно пополам: `_history_window`, бюджет 8 запросов.
- Поиск по сделкам тоже делится окнами: `_window_trades`.
- Прочитанные чужие ордера запоминаются в намерении (`foreign`), повторно их детали не запрашиваются.
- Не хватило бюджета — поиск неполон, намерение остаётся, второго входа нет.

**Сверочные скрипты** (`weex_monitor_common.cid_owner`):
- свой префикс → BOT; префикс другой сетки → OTHER;
- `b7g` без знака известной сетки → неизвестен.
- 125f4c7: номера первых дней BTC (09.10 11:31 … 10.10 05:38, проверено по деталям ордеров) имели формат `b7g` + сторона + вид, без буквы символа (`b7gLe…`, `b7gSt…`). Регулярка `b7g[LS][a-z]\d` относит их к BTC. Без этого сверка BTC теряла 37 ордеров; теперь сходится до цента: 80 сделок сетки, 11 ручных. Знаки L/S новым сеткам давать нельзя.

### 2.2 Параллельный проход (834887d)

**Было.** Сетки шли по очереди под одним `STATE_LOCK`. С пятью живыми каждая обновлялась раз в 30–45 с, тейк после исполнения входа ставился с той же задержкой.

**Стало.** `ThreadPoolExecutor` на все сетки, `STATE_LOCK` держится весь проход сеток, команды `/weex` ждут его конца. Внутри прохода `STATE_LOCK` никто не берёт.
- Клиент WEEX — urllib на каждый запрос, общее только `_offset_ms`; синхронизация часов — до потоков.
- Общий потолок (`_room_shares`). За проход сетка ставит не больше одного нового входа на сторону. Поэтому каждой выдаётся `free − Σ (order_qty × ask × 1.01 × число сторон)` по всем ОСТАЛЬНЫМ живым включённым сеткам. Сумма новых входов прохода ≤ free.
- У самого потолка это строже очереди. Пример: свободно $150, две сетки по $100 — по очереди прошла бы одна, параллельно не пройдёт ни одна.
- Цена символа не прочитана — у соседей места нет.
- Тренд проходит после сеток, по свежему свободному месту.

**Замер после деплоя.** Новые сетки обновляются раз в ~25–30 с, а не 30–45 с. Каждый проход ждёт самую медленную сетку — старую BTC с открытыми лотами — плюс `poll_sec` 10 с. Следующий шаг, если нужен: свой цикл у каждой сетки, без общего барьера.
