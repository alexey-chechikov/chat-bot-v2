## 2. Обозначения и условия

Зелёная G = TEMA50, жёлтая Y = TEMA100, красная R = TEMA200, голубая B = EMA200 от закрытий; Г4 — голубая 4ч, Г1 — голубая 1ч. Значения 4ч на часе берутся по последней закрытой свече 4ч. Формулы: `research/market_regimes_20261102/mr_data.py`.
Данные: Binance spot, 01.2018 – 05.11.2026 (ETH до 02.11.2026), только закрытые свечи.
Результат сделки = ход − 0.136% − фандинг, в % номинала. Суммы не накапливаются: при $1000 на сделку 1% = $10. В одном часе стоп раньше тейка.
Периоды: A 2018–2021, B 2022–07.2024, C 08.2024–05.11.2026, в таблицах «A / B / C».
«Лучше случайного» — доля случайных наборов с суммой ниже моей, 999 повторов.

Ворота кандидата: плюс в A, B и C; n ≥ 100; нижняя граница 95% ДИ среднего выше нуля; лучше случайного минимум в 95%; ETH не противоречит. Участки оператора выбраны глазами и проверкой не считаются.

## 7. Мои ошибки, уже найденные

1. **Знак шорта в `tp_blue.outcomes`.** Цены шорта зеркальные (1/цена), результат считался как `entry/px − 1`, то есть с обратным знаком. Шорт-строки первой версии таблицы были перевёрнуты. Оператору эти числа не сообщались. Исправлено, `out/tp_blue_table.csv` пересчитан.
2. **Метка `blue>G` заглядывает вперёд.** Её получает только шорт от голубой, переживший стоп. Отдельно она даёт 62 сделки и +93, вместе с остановленными 115 и +17. В выводах считается только вместе.
3. **Устаревшая SMA100 в журнале.** `sma100` из `mr_data.daily_regime` — NaN после неполного дня; при взятии последнего значения она устаревала на 100 дней. В `journal.py` заменена на скользящую по имеющимся дням. На правила не влияла.
4. **Оценка сеткой вместо позиции.** На участке 2 я ответил оператору «приоритет шорт под голубой — нет» по деньгам сетки (перекладка по голубой −$262). Позицией это лучшее правило. Сетка и позиция дают разные ответы на один вопрос.
5. **Разбивка по причине закрытия** («деньги дают выходы по цели и далеко») идёт по результату и ничего не доказывает.
