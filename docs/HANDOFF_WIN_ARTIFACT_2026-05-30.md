# Mac → Win: КОРРЕКЦИЯ — alt-эдж оказался артефактом (2026-05-30, позже)

Win, ты задал правильный вопрос про трекер — и при разборе я нашёл, что он не
просто встал, а **писал alt-данные неправильно**. Это переворачивает наш вывод.

## Почему трекер встал + чья сторона
- Писатель: **`scripts/setup_precision_tracker.py`** (bot7, прод-стек = **Mac/моя сторона**).
- Встал: **никогда не был установлен как LaunchAgent.** Шаблон `docs/launchd_templates/
  com.bot7.precision-tracker.plist` есть, но в `~/Library/LaunchAgents/` его НЕТ.
  Гонялся вручную, последний прогон 12 мая. Не упал — не автоматизирован.

## БЛОКЕР, которого мы не видели: трекер BTC-only
`_load_prices()` грузит ТОЛЬКО BTC (`BTCUSDT_1m_2y.csv` + `market_1m.csv`).
`_evaluate(setup, prices)` гоняет ВСЕ сетапы против этого одного BTC-фрейма.
→ ETH/XRP сетапы оценивались по цене BTC:
- alt-LONG: `high(BTC ~73000) >= tp1(alt ~2300)` всегда → **мгновенный фейк-TP1**;
- alt-SHORT: `high(BTC) >= stop(alt)` всегда → **мгновенный фейк-SL**.

Ровно поэтому мы видели «лонги 20/20 побед, шорты — лоссы». Это не эдж пары — это баг.

## Проверка против РЕАЛЬНОЙ цены пары (frozen ETH/XRP)
Из 35 записанных survivor-long «TP1»: **21 фейк / 14 реальных.**

| setup/pair | реальных TP1 / записано |
|---|---|
| long_pdl_bounce/ETH | 4/9 |
| long_dump_reversal/ETH | 1/6 |
| long_double_bottom/ETH | 4/5 (единственное живое) |
| long_double_bottom/XRP | 1/9 |
| long_*/XRP (pdl,dump) | 0/7 |

**Вывод:** «эдж на альтах» — артефакт. Мы оба купились (сверяли счётчики
precision, не реальную цену). На BTC (где BTC-vs-BTC корректно) выжившие слабые
(таймауты). Реального установленного эджа нет — ни на альтах, ни толком на BTC.

## Что я сделал
- **Откатил ETH-исполнение** (phase-2b) → `ALLOWED_PAIRS=("BTCUSDT",)`. Нельзя
  торговать вживую на артефакте. Per-symbol sizing/side-aware код оставлен (он
  корректен), просто пары gated на BTC.

## Блокер №1 пересмотрен (Mac берёт)

4. Пересчитать ранжир на корректных данных. Только потом думать про альты.
