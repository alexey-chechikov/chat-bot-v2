## Что ещё исправить до допуска в подтверждающую C1

1. **ATR пока использует будущее относительно снимка.** [outcomes.py:174](https://github.com/alexey-chechikov/chat-bot-v2/blob/3db1d5eddbef5702f8ef7589d2436161c85f3d61/services/coinglass_web/outcomes.py#L174) запрашивает часы до minute-anchor, например07:01. API выбирает свечи по openTime: полный час07:00–08:00 попадает в ответ при досверке через сутки. Его high/low/close не были известны на снимке07:00:23. Нужен фильтр фактического closeTime<=времени фиксации признаков и замороженный каузальный ATR. Изменение только будущего high этого часа синтетически меняет ATR с0.2 на64.4786.
2. **60 минут ещё не гарантируют одинаковую сетку.** Живые корзины начинаются от A, например07:01–08:01; историческая база построена по UTC-часам07:00–08:00. Нужны одна фаза, одинаковый стартовый open и одинаковое определение ATR/дедлайна. C1 ниже закрепляет фазово согласованные корзины из минутных данных.
3. **Пропущенное утро ещё может заменяться поздним.** [table():214](https://github.com/alexey-chechikov/chat-bot-v2/blob/3db1d5eddbef5702f8ef7589d2436161c85f3d61/services/coinglass_web/outcomes.py#L214) удаляет `missing`/отсутствующую базу до выбора первого утреннего ID. Первое07:00 `missing` и второе07:20 `upper` даютn1, upper100%. Нужен registry назначенного запуска до quality/outcome-фильтров. `none` исправлен, но это не покрывает `missing`.
4. **Старые времена и новая серия не объединяются.** `ts+2 минуты` — предположение, не доказательство времени получения v0. Для C1 нужны подлинный captured timestamp, версия и preregistered forecast, причинно зафиксированная база с SHA и численными q. Переработанные старые снимки остаются retrospective/exploratory.

Два оставшихся дефекта воспроизведены на точном коде, с заблокированной сетью и синтетикой: [REPRODUCTIONS_V1.json](../research/coinglass_v1_reply_review_20261018/REPRODUCTIONS_V1.json), [скрипт](../research/coinglass_v1_reply_review_20261018/reproduce_v1.py). PASS означает воспроизведение ошибки, не подтверждение корректности production.

## Назначенный разбор

- **Дата:23.10.2027 12:00 Europe/Warsaw.** Заморозка данных22.10.2027 12:00.
- Календарная серия:19.10.2026–18.10.2027,365 назначенных утр07:00. Минимум300 заранее допустимых прогнозов, минимум95% полных будущих окон; неизвестные прогнозы остаются в консервативных bounds, не удаляются.
- Основной показатель:`D_hat=mean(Y_low−q_stronger_high)` — превышение частоты первого достижения более сильной выбранной зоны над геометрической ценовой базой.
- **Порог:нижняя односторонняя97.5% bootstrap-граница строго выше+5п.п.** Одна проверка, α0.025,10 000 совместных bootstrap-повторов,7 календарных дней в блоке,PCG64 seed20261018. Это приближённая процедура, не гарантия мощности/ошибки при любой зависимости.
- C1-база:730 исторических дат18.10.2024–17.10.2026, тот же локальный утренний HH:MM и фаза, frozen минутные цены, причинныйATR14; минимум700полных исторических окон. Вариант2020–14.10.2026/все UTC-часы — другой вторичный benchmark.
- До C1 readiness день остаётся `not_ready`; его нельзя задним числом заменить v1-исходом. Не переносить дату разбора ради накопления удачных результатов. Все подробности, bounds, допуски и bootstrap записаны в [полном C1-протоколе](COINGLASS_CONFIRMATORY_PROTOCOL_2026-10-18.md).

Это заранее выбранная спецификация новой серии, а не утверждение, что текущий код уже её выполняет. Одного года может не хватить на умеренный эффект. Неуспех не доказывает эквивалентности базе, успех не доказывает прибыльности сделки.

## Разработчику Mac: запрос для завершения передачи сбора

Основной сбор переносится на Mac. Пользователь уточнил условие: **Windows daily ставится на паузу после фактической сверки настроек**. Ранее он уже был приостановлен без такой сверки; это действие не выдаётся за подтверждённый паритет. Сейчас расписание восстановлено до выполнения указанного условия. Архивы и старый пилот не удалены.

У себя GPT прочитал реальный последний Windows-пакет18.10.2026 и его настройки, не только текст протокола. Пакет частичный по числам/матрицам, но явные настройки сохранены. Референс без сырых данных: [WINDOWS_SETTINGS_REFERENCE.json](../research/coinglass_v1_reply_review_20261018/WINDOWS_SETTINGS_REFERENCE.json).

**Просьба к разработчику Mac, не к пользователю:** опубликуй один минимальный производный экспорт `docs/COINGLASS_MAC_HANDOVER_METADATA_2026-10-18.json`. Сырые DOM/JPEG, рыночные ряды, Telegram IDs, ключи и сведения счёта публиковать не нужно. Нужны:

1. Фактические `run_id`, started/captured/finished UTC и статус каждого источника. Разделить ожидаемые настройки и **settings_observed**, реально прочитанные из загруженной страницы; URL/константа в коде не заменяет selector state.
2. Для Model1 heatmap:Binance,BTCUSDT perpetual,pair,24h,threshold0.85,liquidation map enabled. Для orderbook:Binance BTCUSDT perpetual,15m,merge1. Для spot depth-delta:BTC,USD,15m,±1%,Delta. Для actual liquidations:BTC,все покрываемые биржи,окна1/4/12/24h. `liquidation-levels` хранить отдельно: это не та же heatmap Model1.
3. По каждому источнику — список локально сохранённых файлов/типов и SHA256, признак успешной загрузки графика/чисел и неизвестной свежести провайдера. Недоступное null с причиной, не «совпало по умолчанию».
4. Подтверждение, что утренний обзор реально использует этот Mac-пакет:дата и время доставки, provenance/хеш локального журнала доставки, без личных идентификаторов. Сам факт наличия расписания не доказывает доставку.

После получения экспорта GPT сопоставит поля с Windows-референсом и запишет результат `PASS/FAIL/UNKNOWN` по каждому. **Одного полного подтверждённого пакета достаточно для проверки настроек; не требуется держать дубликат ещё три дня.** При PASS Windows `coinglass-2` ставится на паузу с сохранением определения/архивов. При расхождении конкретные поля возвращаются разработчику в следующем отчёте; согласие пользователя повторно не запрашивается. Старая `coinglass` — только досверка прежнего пилота, это отдельное обязательство.

Ни доступ к Mac, ни вызов его служб из этого чата не выполнялся. Проверка метаданных не превращается в новый Windows-сбор рынка. Опубликованный экспорт — свидетельство provenance от разработчика; независимое чтение частных Mac-артефактов без доступа не заявляется.
