# Тренд 4h ETH/XRP: проверка живого правила вне периода отбора. Протокол (15.10.2026, до расчётов)

**Вопрос.** Держится ли правило на периоде, где его параметры не подбирались? Исполнение — по правилам бота на минутах, с расходами WEEX и фандингом.

Это единственное правило с плюсом за 2 года: тренд 4h ETH/XRP, `services/weex_trend` + `tools/trend_state`, сейчас бот холостой. Цифры: +$1 867 при риске $50, последний год +$209, просадка −$624. Их посчитали на тех же двух годах, на которых правило отбирали (28.07 и 10.10). Внутрибарового аварийного стопа в том расчёте не было.

**Исходы:**
- квалифицируется → ручная карточка «вход / стоп / выход / размер» и алерт TradingView;
- нет → тренд убирается из «что держится».

Параметры и правила ниже после первого расчёта не меняются. Другая геометрия — новый протокол.

## 1. Данные

- **Символы.** Binance USDⓈ-M perpetual, 1m: ETHUSDT и XRPUSDT — решение. BTCUSDT — вне решения, отрицательный контроль: при отборе 28.07 BTC не прошёл.
- **P1 — период, где параметры правила не подбирались.** С первой минуты UM-истории символа до 2024-05-14 23:59 UTC.
  - Источник: месячные архивы `data.binance.vision/data/futures/um/monthly/klines/<SYM>/1m/`. Каждый архив сверяется с `.CHECKSUM`; несошедшийся — отказ.
  - Файлы: `backtests/frozen/<SYM>_UM_1m_early.csv`, вне git, sha256 — в manifest.
  - **Честная оговорка:** семейство 4h-пробоев (Дончиан 20/55) уже смотрела лаборатория индикаторов TV 05.10 на спотовых 1h с 2017–2018. Поэтому P1 — «параметры правила на ней не подбирались», а не «никем не виденный период». Так и пишется в вердикте.
- **P2 — просмотренный период отбора.** С 2024-05-15 00:00 до последней полной 4h-свечи в `backtests/frozen/<SYM>_UM_1m.csv` (существующие файлы). Решение по P2 не принимается, кроме ворот 4.
- **Склейка P1+P2 непрерывная.** На шве минуты не должны теряться или дублироваться; перекрытие сверяется по ценам, расхождение — стоп.
- **Сетка минут.** Только минуты k·60 000 мс; дубли и пропуски считаются. 4h-свеча — UTC-якорь 00:00 + n·4h. Полная — при 240 валидных минутах по критерию `scripts/ohlc_grid`:
  - уникальные минуты на сетке;
  - конечный OHLCV;
  - low ≤ min(open, close), high ≥ max(open, close);
  - объём ≥ 0.
- **Неполная 4h-свеча.**
  - Остаётся в ряду индикаторов, как в живом коде (resample + dropna; свеча без минут выпадает).
  - Сигнал входа и выход по закрытию на ней не исполняются.
  - Пропущенный выход исполняется на закрытии следующей полной свечи, если условие ещё выполнено.
  - Аварийный стоп внутри неё проверяется по имеющимся минутам.
  - Число таких свечей и затронутых событий показывается.
- **Фандинг.** Binance `/fapi/v1/fundingRate` с начала истории; `backtests/frozen/<SYM>_funding.csv` дополняется ранним периодом. Интервалы между расчётами и пропуски показываются.

## 2. Правило — как живой код, без изменений

- 4h-свечи из 1m: open — первая минута, high — max, low — min, close — последняя.
- **ATR14** — простое скользящее среднее TR за 14 свечей (`tools/trend_state._atr`). TR = max(high−low, |high−close₋₁|, |low−close₋₁|); у первой свечи — high−low.
- **ADX14** — `tools/trend_state._adx`:
  - +DM = up, если up > dn и up > 0, иначе 0; −DM зеркально; up = Δhigh, dn = −Δlow;
  - TR, +DM, −DM сглаживаются EWM alpha = 1/14, adjust = False (затравка — первое значение);
  - +DI = 100·EWM(+DM)/EWM(TR), −DI аналогично;
  - DX = 100·|+DI − −DI|/(+DI + −DI); ADX = EWM(DX) с alpha 1/14, adjust = False.
- **Прогрев.** Первые 120 свечей ряда — входов нет.
- **Канал.** HH = max(high), LL = min(low) — по предыдущим 30 свечам, без текущей.
- **Вход** (только когда по символу нет позиции):
  - LONG — close > HH и ADX ≥ 20;
  - SHORT — close < LL и ADX ≥ 20;
  - на свече выхода новый вход не ищется, только со следующей.
- **Пик.** LONG — high свечи сигнала, далее max с high каждой следующей закрытой свечи. SHORT — зеркально, по low.
- **Chandelier** на закрытии свечи j: LONG — пик_j − 3·ATR_j, SHORT — пик_j + 3·ATR_j. Начальный считается на свече сигнала.
- **Исполнение входа.** Рыночный вход на open первой минуты после закрытия свечи сигнала.
  - Если этот open уже за начальным Chandelier (LONG: open ≤ Chandelier; SHORT: open ≥ Chandelier), входа нет: это живой «пропуск: цена уже за стопом», он учитывается в воронке.
- **Выход по закрытию.** На закрытии полной свечи j после свечи сигнала: close_j < Chandelier_j (LONG) или close_j > Chandelier_j (SHORT) → рыночный выход на open первой минуты после закрытия.
- **Аварийный стоп на бирже** (`services/weex_trend`, `emergency_buffer_pct` 1.5, `stop_update_min_pct` 0.2):
  - триггер = Chandelier·(1 − 1.5%) для LONG, Chandelier·(1 + 1.5%) для SHORT; округление к тику (ETH 0.01, XRP 0.0001, BTC 0.1) в сторону от цены;
  - начальный — по начальному Chandelier;
  - переставляется на закрытии свечи, только если Chandelier сдвинулся **в пользу** позиции не меньше чем на 0.2% от последнего учтённого (храповик). Выход по закрытию при этом сверяется с текущим Chandelier, даже если тот ушёл против позиции;
  - новый триггер действует с первой минуты после закрытия свечи;
  - проверка — с минуты, следующей за минутой входа: low ≤ триггер (LONG) или high ≥ триггер (SHORT);
  - исполнение LONG — min(триггер, open этой минуты), то есть гэп через стоп исполняется по open; SHORT — зеркально; плюс проскальзывание;
  - внутри свечи аварийный стоп проверяется по её минутам раньше, чем проверка закрытия. Сработал — позиции на закрытии уже нет.
- **Конец данных.** Позиция, открытая на конец данных, оценивается по последнему close, помечается censored и в n завершённых не входит.

## 3. Размер, расходы, учёт

- **Размер** — как `state/weex_trend_config.json`:
  - qty = min(50 / (|E − триггер₀| + 2·0.0005·E), 3000 / E), где E — open минуты входа без проскальзывания;
  - округление вниз к шагу: ETH 0.001, XRP 10, BTC 0.001;
  - qty = 0 → пропуск.
- **Комиссия** — тейкер 0.048% на каждую ногу (вход, выход по закрытию, аварийный стоп) от цены исполнения.
- **Проскальзывание** — 0.02% на ногу против позиции. Чувствительность ×2 (0.04%) — полный повторный прогон, а не вычитание.
- **Фандинг** — на каждом расчёте с вход < fundingTime ≤ выход: платёж = −side·qty·markPrice·rate (LONG платит при rate > 0). Нет markPrice — берётся close минуты расчёта.
- **R** = net PnL / (qty·(|E − триггер₀| + 2·0.0005·E)) — запланированный риск. $ — при фиксированном риске $50, без сложного процента.
- **Портфель ETH+XRP.** Состояния монет независимы, PnL суммируется. Совместная кривая капитала — по закрытиям 4h с плавающим результатом по close; макс. просадка — по ней.
- **Отнесение к периоду** — по времени входа.

## 4. Контроли — тот же цикл исполнения

- **C1 «случайный вход, тот же выход».** На каждый вход стратегии берётся случайная полная 4h-свеча:
  - того же символа, той же стороны, того же периода (P1/P2);
  - с тем же часом закрытия (одним из 6);
  - из того же терциля ATR14/close (терцили — по всему ряду символа).
  
  Дальше — вход на open следующей минуты, тот же пик, Chandelier, аварийный стоп, размер, расходы и фандинг. Одна позиция по символу: кандидат берётся только после выхода предыдущей контрольной позиции; если кандидатов нет, вход выпадает (число показывается). 999 повторов, seed 20261015. Ранг = (k+1)/1000, где k — число повторов со средним R ≥ стратегии.
- **C2 «пробой без ADX»** — то же правило без фильтра ADX.
- **BTCUSDT** — отдельно, вне решения.

## 5. Чувствительность — заранее объявлена, не для выбора

- 16 ячеек на P1: LB ∈ {20, 30, 45, 60} × K ∈ {2, 2.5, 3, 4}, остальное базовое. Показываются все.
- Смещение якоря 4h-свечей: 00, 01, 02, 03 UTC.
- Задержка входа +5 мин (open шестой минуты после закрытия).
- Без аварийного стопа, только выход по закрытию — для сверки с прежним бэктестом.
- ×2 проскальзывание.

## 6. Ворота

Решение принимается по портфелю ETH+XRP на P1. Обязательны все ворота.

| № | Ворота |
|---|---|
| 1 | Среднее R после расходов > 0 и при ×2 проскальзывании > 0 |
| 2 | Завершённых сделок ≥ 100, непустых ISO-недель ≥ 30 |
| 3 | Нижняя граница 95% ДИ среднего R > 0 (бутстрап блоками по ISO-неделям, 9 999 повторов, seed 20261015) |
| 4 | Время: P1 делится по календарю на три равные части, последняя треть > 0 сама по себе; P2 > 0 |
| 5 | Соседи базовой ячейки (30, 3): (20, 3), (45, 3), (30, 2.5), (30, 4) — все > 0 на P1 |
| 6 | Все 4 смещения якоря > 0 на P1 |
| 7 | Ранг C1 ≤ 0.05 |

**Статусы:**
- «Квалифицирована» — пройдены все ворота;
- «Отвергнута» — среднее R на P1 ≤ 0;
- «Не квалифицирована» — среднее > 0, но не все ворота пройдены;
- при n < 100 добавляется «(n < 100)».

**Живое против бэктеста — диагностика, не ворота.** Живые сигналы `state/trend_signals.jsonl` сопоставляются по времени со сделками P2 (±4 ч, та же сторона). Каждое расхождение разбирается. Живые сигналы до 17.09 содержат фантомные входы по незакрытой свече: 9 из 20, баг исправлен. Их выделить отдельно.

## 7а. Дополнение 15.10 — решение по данным, принято до просмотра результатов XRP

Подготовка данных показала дыру в месячных архивах XRPUSDT: нет 7 200 минут. Это 2022-02-26 00:00…02-28 23:59 и 2022-04-01 00:00…04-02 23:59, итого 30 пустых 4h-свечей. В дневных архивах Binance с `.CHECKSUM` и в REST эти минуты есть.

Решение:
- **основной расчёт — по тексту протокола, как есть**: дыры остаются, неполные и пустые свечи обрабатываются по §1;
- **объявленная чувствительность** — XRP с этими 5 днями из дневных архивов (сверка с `.CHECKSUM`, тот же формат). Ворота считаются по основному расчёту.

На момент этого решения из результатов были видны только базовые цифры ETH независимой реализации (у ETH дыр нет). Цифры XRP не просматривались.
