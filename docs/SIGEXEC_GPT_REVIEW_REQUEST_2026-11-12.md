## Что проверить

Нужны дефекты, которые ведут к потере денег или к расхождению с движком. Каждый — с воспроизведением: тест на имитаторе `exchange/sim.py` или поддельный HTTP, как в `tests/services/sigexec/test_lines_adapters.py`.

1. **`services/sigexec/executor.py` — ядро.** Проверить инварианты:
   - намерение (`SENDING`) пишется на диск до отправки;
   - `UNKNOWN`/`SENDING` — не конечный статус: новой заявки той же работы нет, пока поиск по cid не дал конечный;
   - `ABSENT` ставится только после `unknown_grace_s` и только если `order()` вернул `None`;
   - учёт идёт по накопленному `filled` каждой заявки: позиция эпизода = вход + добор − выход/цель/стоп/извне;
   - одна живая заявка на работу (вход, выход, рыночный добор);
   - выход сначала снимает стопы, цель и вход, ждёт их конечного статуса, потом закрывает остаток reduceOnly;
   - потолок `cap_usd` считает позиции, живые входы и бронь добора;
   - после `max_rejects` отказов подряд роль встаёт, сообщение раз в час; выход повторяется раз в минуту;
   - если аварийный уровень уже пройден — выход сам, без стопа;
   - учёт пропал при живом журнале → `Halt`;
   - сверка `_audit`: позиция стороны меньше своего учёта два прохода подряд → запись «извне». Чужие контракты той же стороны (сетки, ручные) не трогаются.
2. **`exchange/bybit.py`, `exchange/okx.py`** написаны по документации v5. Вживую проверены только публичные методы (`instrument`, `book`). Проверить по документации:
   - статусы и коды ответов (отказ / неизвестно / «нет такой» / «уже конечная»);
   - Bybit: `triggerDirection` по стороне, `positionIdx` хедж-режима, поиск `realtime` → `history`, `orderFilter=StopOrder`;
   - OKX: объём в контрактах (`ctVal` 0.01), `ordType=trigger` + `orderPx=-1`, исполнение сработавшего алгоритма по `ordId`, отмена алгоритма по `algoId`, `fee` со знаком минус = заплачено.
3. **`exchange/weex.py`** — обёртка проверенного клиента сеток. Проверить:
   - поиск по cid: открытые → история окна делением пополам → `Incomplete`, если неполная;
   - комиссия по `userTrades`;
   - сработавший стоп: `algoStatus` / `actualOrderId`;
   - `{}` на постановку → `Unknown`.
4. **`lines.py` + `strategy.py`** — линии из часовых свечей любого источника и нужная позиция из движка `services/btc_signals/engine.py`. Проверить, нет ли заглядывания: `B4p`, `j`, ранг и вес.
5. **`research/sigexec_20261112/limit_tactics.py`** — методика замера лимиток: лимитка исполняется, только если цена прошла сквозь уровень на тик; добивка рыночным с проскальзыванием 0.01%.

## Чего нет (известно, не дефекты разбора)

- Торговые методы Bybit и OKX не проверены на бирже: нужен тестнет Bybit или демо-счёт OKX, ключи вписывает оператор.
- Нет зачистки сирот по префиксу на бирже. Пропажа учёта = `Halt`, сирот при живом учёте быть не должно — проверить, так ли это.
- Фандинг в учёт сделки не входит. За 2 года при базе $1000: система −$17, 432 −$16.
- На WEEX потолок исполнителя не связан с общим потолком сеток (`services/weex_grid/portfolio.py`), а стороны общие с сетками и ручными сделками. Рекомендация — отдельный счёт.
- Нет службы launchd и проверки сообщений Telegram вживую. Бумажный режим исполняет по снимкам стакана раз в 5–30 с.
- Один символ (BTCUSDT) на процесс.
