# Дельта агрессора на 15m (ядро ATLAS «объём против цены») — протокол ДО расчётов

Основание: ТЗ `docs/ATLAS_TRADINGVIEW_DATA_RESEARCH_SPEC_2026-10-13.md` §6–8 (применение B — ручной интрадей 15m),
сайт ATLAS (nzttrade.com/atlas, /atlas1: «объёмные пузыри», «противоположные знаки дельты и свечи», боты 4-P и C+M с
заявленным винрейтом 70% / 63% без методики). Слово оператора 14.10 «делай». Правила ниже фиксируются до первого
прогона; результаты — `docs/ATLAS_DELTA_RESULTS_2026-10-14.md`. Всё, чего нет в источниках, — **[формализация]**.

## Данные
- Binance USDⓈ-M перпетуал BTCUSDT и ETHUSDT, 1m klines `/fapi/v1/klines` с 2024-05-15 до последней закрытой
  минуты выгрузки (`research/atlas_data/fetch_binance_um_1m.py`, файлы `backtests/frozen/<SYM>_UM_1m.csv`, sha256 —
  в отчёте). UTC.
- **Дельта агрессора** минуты = 2 × taker_buy − volume (поле биржи k[9]: объём, где покупатель — агрессор). Это
  классификация биржи по каждой сделке, суммированная за минуту, — не оценка TradingView по направлению младших
  свечей. Дельта 15m-свечи — сумма 15 минут; нормированная nd = дельта / объём (NA при нулевом объёме).
- Footprint (дельта по уровням цены внутри свечи, «в фитиле») **не проверяется**: нужны aggTrades (≈16 ГБ BTC +
  19 ГБ ETH за 29 мес.) — отдельное решение оператора.
- Исполнение — на WEEX (наша площадка): тейкер 0.048%, мейкер 0.016% (замер), проскальзывание 0.02% на каждое
  рыночное исполнение, чувствительность 0.04%. Цены — Binance как прокси WEEX **[формализация]**; базис не моделируется.

## Тест 1 — «расхождение дельты и свечи» (самостоятельный сигнал)
- Порог по прошлому: P10 и P90 nd по всем 15m-свечам предыдущих 20 завершённых UTC-дней (только прошлое).
- **LONG («продажи поглощены»):** nd свечи ≤ P10 и close ≥ open. **SHORT («покупки поглощены»):** nd ≥ P90 и
  close ≤ open.
- Вход — open следующей свечи, рыночный; выход — рыночный по open через 4 свечи (1 ч) **[формализация]**; одна позиция
  на символ одновременно; сигналы во время позиции пропускаются. Результат — в % цены после расходов (без размера).
- Контроль: случайные свечи той же стороны, сопоставленные по 6-часовой корзине UTC-времени суток и терцилю
  волатильности (диапазон предыдущих 20 свечей / цена), тот же выход; 999 повторов; ранг (k+1)/(n+1) среднего.
- Сравнение: та же крайняя дельта «по направлению» (nd ≤ P10 и close < open → LONG, зеркально SHORT) — проверяет,
  что важно именно расхождение, а не крайняя дельта сама по себе.

## Тест 2 — ценовой сетап + добавки (как в ТЗ GPT §8B)
Механика — сетап A из `docs/GOLD_LIQUIDITY_SWEEP_PROTOCOL_2026-10-13.md` §3 без изменений (ложный пробой минимума
прошлого UTC-дня на 15m, LONG, подтверждение ≤3 свечей, стоп = low сигнальной − 2 тика, цель 2R, ≤4 ч, риск 0.25%
капитала $3 000, дневной лимит 0.75%), тик BTC 0.1 / ETH 0.01, шаг объёма BTC 0.001 / ETH 0.01, плечо ≤ 20×,
комиссии WEEX. Версии: A; B = A + close подтверждения выше дневного VWAP; **Cn** = B + nd сигнальной свечи ≤ P10
(как выше) — аналог footprint-правила ТЗ на уровне всей свечи, не фитиля **[формализация]**; En = B + LVN
(протокол золота п.4). Контроль Cn: случайные подвыборки B того же размера с тем же составом по 6-ч корзинам и
терцилям волатильности, 999 повторов.

## Проверка и статусы (как в протоколе золота)
Хронологический разрез 70/30 по каждому символу; правила не подбираются. ДИ среднего — бутстрап блоками по ISO-неделям,
9 999 повторов. Статусы: **«Кандидат на малый тест исполнения»** — среднее после расходов > 0 на всём периоде и на
контрольной части, нижняя граница ДИ > 0, n ≥ 100, > 0 при удвоенном проскальзывании, ранг контроля ≤ 0.05;
**«Недостаточно данных»** — n < 100 или ДИ включает 0 при оценке > 0; **«Отвергнута»** — среднее после расходов ≤ 0
на всём периоде или на контрольной части. BTC и ETH — не независимые подтверждения.
