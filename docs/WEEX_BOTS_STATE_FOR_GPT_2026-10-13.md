## 3. Что изменилось 12–13.10 (в этом пуше)
- **Данные:** `com.bot7.ohlcv-gapfill` писал последнюю минуту каждого часового прогона недозакрытой (BTC 3 206,
  ETH 3 102, XRP 2 982 минут с 14.05.2026; объём ~53%). Корень — `scripts/ohlcv_gapfill_all.sh` (target-end =
  now−2 мин по минуте); перекачка — `research/weex/repair_frozen_1m.py` (байтами, CRLF сохраняется, отмена при
  дозаписи файла во время работы, сверка всех полных часов 1h). Влияние на бэктест сетки BTC 0.6/1.4 0.0036/$12k —
  $0.00, ETH — −$0.02.
- **Проверочные скрипты:** `account_now.py` (новый), `orphan_check.py` (в обе стороны, сетка без учёта),
  `pnl_reconcile.py` (BTC|ETH|XAU, вердикт только по сторонам бота, владелец ордера сверяется по orderId),
  `errors_today.py` (новый: ERROR с причиной + WARNING о деньгах, ротация логов, покрытие).
- **Бэктест-инструменты:** `regime_grid.py` (`--src=` копия снимка + sha256, отказ при несовпадении символа и без
  100 дней прогрева, `--ctl=N` и ранг, XRP), `size_check.py` (ячейки аргументами), `validate_fast.py` (закреплены
  стороны/режим — до этого брал живой конфиг и сверка была пустой; сейчас быстрый сим ниже движка на 3–6%),
  `tools/ginarea_regime_check.py` (параметры CLI, ключ пропуска (from, to, side, gs, target), пустой --spec — отказ).
- **Тест:** `tests/services/weex_grid/test_weex_release.py::test_manual_short_untouched_by_regime_close` — ручной шорт
  и ручной тейк оператора на переданной стороне + ручной лонг на стороне бота переживают закрытие лонгов по
  режиму, неизвестный режим и возврат режима; проверен 4 мутациями (бот считает чужие ордера своими; снимает всё
  на стороне; закрывает и шорт; закрывает всю позицию стороны вместо лотов) — все пойманы.
- **Правила (CLAUDE.md, скилы `claude_skills/`):** деплой — пока сетка не в dry_run, любой kickstart/автоперезапуск
  launchd грузит всё дерево → торговый код без «да» оператора в живом дереве не держать; цикл с GPT — стоп при
  файлах вне docs/, zip-репродукции не запускать (на маке живые ключи).
- Полный набор тестов: 745 passed, 1 xfailed.

## 4. Вопросы к GPT
1. Логика `account_now.py`: пороги живости (60/180 с с учётом паузы цикла после ошибки), флаг halted, проверка
   переданной стороны по сделкам биржи (clientOrderId через `order_info`, сверка orderId), передача без лотов
   (записи нет) — где ложное «ок» ещё возможно?
2. `orphan_check.py`: достаточно ли «лот без тейка = тейка нет среди открытых» без запроса `order_info` (гонка с
   исполнением тейка)?
3. `pnl_reconcile.py`: стороны бота = `sides` + не переданные стороны с остатками в учёте — верно ли для смены
   `sides` без передачи?
4. `repair_frozen_1m.py`: окно гонки с часовым gapfill (сверка размера/mtime после записи tmp, перед os.replace).
5. Риски, которые не закрыты: нет биржевого аварийного стопа у сеток (мак лежит → лоты без сопровождения);
   фандинг лонгам не входит в итог `/weex`; толкование P0 «не закрывать в минус» против закрытия по SMA100 ждёт
   оператора.
6. Слабые места исследований: контроль по отрезкам на 999 повторов локально не воспроизведён (ранги 0.23/0.12 —
   ваши); контроль «то же время в рынке ±1 п.п.» не реализован; `regime_grid` с движком `eg.Grid` не сверен;
   у клона GinArea 4568400511 смещения Dynamic (so 0.4 / ioo 0.06) — влияют ли на итог regime_check, не проверено.
