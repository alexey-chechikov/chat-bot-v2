# PUMP / DUMP FILTER v2 — ТЗ

**Статус:** проект, без кодинга. Зафиксировано 2026-05-22.
**Цель:** усовершенствовать механизм защиты GinArea-ботов от резких движений —
идентифицировать памп/дамп, отличить настоящий тренд от ложного выноса,
и решить, паузить бота или дать гриду отработать спайк.

Предшественник: `tools/_backtest_pump_freeze.py` (pump_freeze v1) — детект
только pump-up по `pct_30m`, классификация trend/whipsaw/partial постфактум
через 4ч lookahead. v2 расширяет это.

---

## Постановка задачи

Резкое движение цены может быть двух природ, и для грид-бота это
**противоположные** ситуации:

- **Настоящий памп/дамп (trend)** — цена уходит и не возвращается. Грид-бот
  набирает позицию против движения и копит DD. → надо **freeze**.
- **Ложный вынос (whipsaw)** — спайк с возвратом к исходному уровню. Это
  **профит** грид-бота — он на этом зарабатывает. → freeze НЕ нужен, мешает.

Проблема v1: trend и whipsaw в момент входа в движение **неразличимы** —
обе резкие свечи. v1 различает их только через 4ч (постфактум), когда бот
уже схватил DD. v2 должен дать **раннюю дискриминацию** (за 30-60 минут).

Охват: **симметрично** — SHORT-боты защищаем от пампа-вверх, LONG-боты —
от дампа-вниз.

## Phase 1 — каталог событий  *(ведёт Win-Claude)*

Расширить `detect_events` на **обе стороны**:
- pump-up: `pct_Wm ≥ +threshold`
- dump-down: `pct_Wm ≤ −threshold`

Прогон по 2 годам. Для каждого события — профиль:
- амплитуда: pct за 30м + пиковый pct всего движения
- длительность: минут до пика, минут до возврата (если был)
- volume-спайк: объём в окне / медиана 24ч
- OI-дельта: ΔOI за движение (знак — ключевой)
- taker-ratio: перекос buy/sell в окне
- funding на пике
- форма свечей: wick-ratio, ускорение цены (2-я производная)

## Phase 2 — разделение «памп» vs «ложный вынос»  *(Win-Claude)*

На разметке trend/whipsaw посчитать разделяющую силу признаков:

| Признак | Гипотеза | Видно за |
|---|---|---|
| OI↑ vs OI↓ | тренд = новые деньги (OI↑); вынос/squeeze = OI↓ | 30-60 мин |
| volume-профиль | вынос = разовый спайк→тишина; тренд = устойчиво высокий | 30-60 мин |
| taker-ratio | тренд = напор агрессивного тейкера; вынос = тонкий | 30-60 мин |
| funding | экстремальный funding на пике = перегрев → вынос | сразу |
| откат после пика | вынос возвращается ≤60м; тренд держит | постфактум |
| wick-ratio | вынос = длинный хвост (откуп); тренд = тело | сразу |

**Выход:** ранний `score` (виден за 30-60м, не через 4ч).

## Phase 3 — профиль длительности → порог freeze  *(Win-Claude)*

Гистограмма длительности пампов/дампов, медиана и 95-перцентиль →
обоснованный таймаут freeze (v1 фикс 4ч; данные скажут, надо ли менять).

## Phase 4 — маппинг score → действие  *(Win-Claude)*

| Класс | score | Действие |
|---|---|---|
| Настоящий памп/дамп | high | **freeze** — пауза, не набирать в движение |
| Вынос-обманка (whipsaw) | low | **НЕ freeze** — grid отрабатывает спайк (его профит) |
| Серое (partial) | mid | **freeze с быстрым resume** — короткий таймаут / ранний выход по откату |

Ключевой принцип: фильтр НЕ должен мешать гриду зарабатывать на ложных
выносах. Душим только настоящий тренд.
