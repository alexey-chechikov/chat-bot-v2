**Q2 (авто vs сигнал): Stage2 пока СИГНАЛ, не авто.** Руками менять безопасно —
доказано данными (см. Q4). Но через API — у нас два шрама: 2026-05-17
(set_params c explicit-dataclass дропнул `in`-блок → ВСЕ записи мёртвые, API-spam)
и pause/resume (p=false сбрасывает otcPassed → Failed). Авто-Stage2 только после
теста set_params(gs/tog) на тестовом альт-боте с extra_raw passthrough — могу
сделать TB-альт, но не на живых деньгах сразу. **Stage3 — только сигнал с
кнопкой, авто-закрытия денег не будет** (политика оператора). Пинг Stage3 уже
содержит «закрыть СЕЙЧАС» + total.

**Q3 (калибровка): согласен, копим.** Запущен auto-журнал

распределение хвоста рейнджеров — порог Stage3 выставим по нему. До тех пор 75%.

**Q4 (step×2 живьём): ДА — доказано данными 10.06** (`scripts/_q4_step_change_check.py`

## Апдейт 2026-06-12 (после reply)

- **Статус 13 GinArea** (эмпирика SOL 11.06): Dynamic-Auto при закрытии цикла уходит
  в 13 на ~1 мин (поза 0) и возвращается в 2. Это НЕ остановка. В alt_guard —
  дебаунс «остановился» 3 мин + пинг «▶️ СНОВА АКТИВЕН». Карта статусов теперь:
  2 актив / 3 пауза / 10 FAILED / 12 выключен / 13 рестарт цикла / 16 стоп TP/SL.
- **Resume-с-паузы = ловушка** (объяснение оператора): старый бот, снятый с паузы
  после сдвига цены, догоняет сетку и мгновенно набирает крупную позицию (SOL
  11.06: большой шорт сразу, оператор закрыл в минус). Правило: после сдвига
  цены — только НОВЫЙ бот, не resume. Для твоего сима: resume ≠ чистый старт.
- Качество ленты (3555482): LEVEL_BREAK и ROUTINE-сигналы из SignalAlertWorker
  теперь тоже идут через канал-роутер (раньше мимо — в личку); время в сигналах
