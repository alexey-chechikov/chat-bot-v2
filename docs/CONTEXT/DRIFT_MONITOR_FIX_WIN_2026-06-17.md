# Win → Mac: 2 фикса дрифт-монитора (доказаны на данных 16.06) — 2026-06-17

Из разбора TG 16.06: монитор перепутал рейнджера и дрифтера. Оба фикса в `tools/_grid_drift_monitor.py`,
валидированы (синтетик-кейсы 16.06 + регресс на 10.06 — без регрессии).

## Фикс 1: дискриминатор Stage-3 = ЗНАК total + ДЛИТЕЛЬНОСТЬ пригвождённости (не только глубина мешка)
**Проблема (данные 16.06):** Stage-3 ключился на bag_pct≥75% SL. Это:
- ЛОЖНО крикнул «закрыть» на **MegaHard** (bag 79% SL, но **total +141** → рейнджер, восстановился → STOP-OFF +346/−99 = **+247**). Закрытие в Stage-3 стоило бы ~$100 апсайда.
- НЕ дотянул до Stage-3 на **XRP** (bag 60% SL, но **total −50, pin 1.00 ~14ч** = настоящий дрифтер, бледёт).

**Ключ:** рейнджер = `total>0` (харвест перекрывает мешок); дрифтер = `total<0` + пригвождён долго.
- **Path A (взрыв) с РЕЙНДЖЕР-ГАРДом:** если `total>0` — планка Stage-3 поднята до bag≥95% (иначе не режем винера).
- **Path B (стойкий дрифтер) НОВЫЙ:** `total<0 AND pos_pin≥0.80 AND pinned_neg_min≥120 AND bag≥50%` → Stage-3,
  даже при среднем мешке (грид не доит — режем, не ждём 75% SL).

**Результат (регресс-тест в `__main__`):** MegaHard→Stage 1 (держим ✓), XRP→Stage 3 (режем ✓).
10.06 без регрессии: SOL/XRP рейнджеры ≤Stage 1, WLD дрифтер по-прежнему Stage-3 в total −78.
`pinned_neg_min` = новое поле метрик (минуты серии «поза пригвождена И total<0»).

## Фикс 2: дедуп Stage-алертов (класс `StageAlerter`)
**Проблема:** MegaHard получил 6+ одинаковых Stage-2 «РАСШИРИТЬ ×2» за 14ч, XRP 4+ — спам одного состояния.
**Решение:** эмитить ТОЛЬКО на смену стадии; Stage-3 (actionable) напоминать раз в `REMIND_MIN=60`. Состояние per bot.
```
al = StageAlerter()
if al.should_emit(bot_id, stage, ts):   # True только на переход / Stage-3-напоминание раз в час
    send_tg(...)
```
