## Q1 — Охват 6% vs 12%: подтверждено, механизм точный

**Подтверждаю, но причина точнее, чем «фактический охват 6%».** Тут ДВА разных числа:

| что | WLD | SOL | XRP |
|-----|-----|-----|-----|
| **CONFIG-border** (border_top..border_bottom) | **6.0%** (0.5183..0.4881) | ~ | ~ |
| **адаптер метил** (SPAN=12 → ordcnt=12/step) | 12% | 12% | 12% |
| **реально прошла цена** (диапазон IN-филлов) | 10.6% (0.4588..0.5104) | 3.0% | 2.0% |

**Лик в адаптере:** `_alt_grid_scan.py` считает `ordcnt = SPAN/step` при `SPAN=12`, т.е. кладёт
*количество ордеров под 12%*. Но платформенный Dynamic-Auto выставил **border = 6%**. Те же ~40
ордеров упаковались в 6% вместо 12% → **эффективный шаг вдвое меньше → плотность набора на каждый
% движения ВДВОЕ выше.** WLD прошёл 10.6% вниз — пробил весь 6%-border насквозь, реверс-лонг
продолжил докупать → мешок −181 → tsl −175 сработал.

**Правило (как у GPT «держать risk-density, не step» — но конкретнее):**
> Не доверять `ordcnt × step` как охвату. Реальный охват = **border_top..border_bottom** платформы.
> Инвариант держать: `max_leg_notional / border_span_pct ≈ const`.
> Если border сел с 12% до 6% — **либо `ordcnt = border_span/step` (не 12/step) → вдвое меньше ордеров**,
> **либо явно задать border 12%**, либо вдвое урезать size. Поднимать tsl — худший путь (просто
> разрешает больший мешок). **В адаптер: брать span из реального border, а не из желаемого 12.**

## Q2 — WLD с капнутой лонг-ногой: cap = основная защита, не косметика

Реальные пики из snapshots: **short-пик −3768**, long-пик +4403, худший мешок **−181** при позе 4403.
Линейный пересчёт мешка по доле капа (мешок ≈ линеен по long-позиции на дне):

| maxOpL | абс. кап | мешок (Win, линейно) | мешок (GPT-оценка) | итог |
|--------|----------|----------------------|--------------------|------|
| 1/4 maxOpS | 942 | **≈ −40** | −55 | << tsl, стопа НЕТ |
| 1/2 maxOpS | 1884 | **≈ −77** | −85 | << tsl, стопа НЕТ |
| cap 3000 | 3000 | **≈ −123** | −123 ✅ | в пределах tsl |

Расхождение Win/GPT (−40 vs −55) — потому что при раннем стопе докупки средняя входа лонга выше →
мешок чуть сублинеен; точный пересчёт по лестнице филлов даст промежуточное, **но вывод инвариантен:**
**maxOpL = 1/4…1/2 maxOpS превращает −181 (стоп-аут) в −40…−85 (без стопа).** Это **основное защитное
правило для MARKDOWN-дней**, не косметика. На MARKDOWN BTC 4ч — либо этот кап, либо вообще
**freeze long-entry**.

## Q3 — Сим vs реальный симметричный цикл: что именно убило (семантика стопа ПОДТВЕРЖДЕНА)

Реальная траектория WLD (из snapshots/events):
1. **Short-нога** набралась до −3768, дала **realized +71**.
2. **Реверс short→long @ 08:40 UTC, avg 0.4983.** Лонг докупал падающий нож (BTC 4ч MARKDOWN весь день).
3. **Мешок = `current_profit − profit`** дошёл до **−181** при позе +4403 → пробил **tsl −175**.
4. tsl закрыл всё → **итоговый realized −99** (= +71 short − ~170 long).

**ПОДТВЕРЖДЕНО для сима:** стоп считается по **МЕШКУ (`current_profit − profit`, нереализ),
а НЕ по total PnL.** В момент срабатывания total был ~−110, а мешок −181 → бил мешок. Именно это
сегодня убило WLD. → В симуляторе стоп-условие: `current_profit − profit <= tsl`, **не** `total_pnl <= tsl`.
Long-only сим раньше этого не ловил (нет реверс-фазы); добавить симметричный цикл short→reverse→long.

## Q4 — XRP funding threshold: валидного порога НЕТ, заглушку оставить

**Согласен с GPT: число из локальных артефактов не подставлять.** Проверил свои:
- `funding_extremes_results.csv`: лучший long_only thr 0.02%/48h → PF 3.44, но **fold_pos 2/4** (валится
  на половине walk-forward фолдов), n=22.
- `funding_flip_results.csv` **XRPUSDT**: long thr 0.001/48h → **PF 1.27, WR 50%, DD $706**; short 0.005/72h →
  PF 1.41. Оба слабые (PF ~1.2-1.4, WR монета).
- `pump_event_catalog` funding_at_anchor: диапазон −0.0152%…+0.0724%/8h, mean +0.005%.

**Вывод:** заявленного в handoff «AUC 0.695» в моих артефактах НЕ воспроизводится; funding как
самостоятельный гейт на XRP — слаб (PF 1.27). **Валидного порога у меня нет.** Оставить
**−0.03%/8h как WARN-заглушку**, НЕ промотировать в жёсткий off-switch. Для настоящего гейта нужен
отдельный OOS-прогон funding-флипа на XRP с большим n — пока не делал.

## Что поменять у тебя (итог)

1. **Адаптер:** `ordcnt = border_span/step`, span брать из реального border платформы (не 12). Иначе
   плотность набора удваивается → ускоренный мешок.
2. **MARKDOWN-режим (BTC 4ч под TEMA200):** `maxOpL = 1/4…1/2 maxOpS`, либо freeze long-entry. Это
   главный спасатель (−181 → −40…−85).
3. **Alt-Guard ДЕЙСТВУЕТ, не только варнит** (GPT прав, окно было 40+ мин: 80% SL в 16:14 → стоп 16:58):
   - мешок ≤ 60% tsl → warn;
   - мешок ≤ 75-80% tsl И нога против BTC-режима → pause new IN;
   - мешок ≤ 90% tsl → emergency close.
4. **Profit-lock regime-aware:** short-нога дала +$50-70 и BTC всё ещё MARKDOWN → фиксировать цикл,
   НЕ ждать ttp=100 через симметричный реверс в лонг.
5. **Сим:** стоп по `current_profit − profit`, добавить симметричный short→reverse→long цикл.
6. **Funding:** −0.03%/8h как WARN-заглушка, не жёсткий гейт (нет валидации).
