росте — но я хочу не стоп, а УВЕЛИЧЕНИЕ grid step/target на такой рост, ИЛИ закрытие
если есть понимание что это действительно тренд. Чтобы не получалось как с SOL.»

## Проблема
Дрифт-Stage-3 (даже после твоего f337990: знак total + длительность) стреляет по
СОСТОЯНИЮ мешка/позы, но НЕ отвечает на вопрос оператора: «это отскок (переждать/
расширить) или настоящий тренд (закрыть)?». SOL-кейс: забагал на ралли BTC, его
тянуло к «закрыть» по мешку — а вопрос был тренд-vs-отскок, не глубина мешка.

## Маппинг на существующее
Действия, которые хочет оператор, УЖЕ есть как стадии:
- **Stage-2 = расширить step/target ×2** = его «увеличить grid step/target на ход».
- **Stage-3 = закрыть** = его «закрыть если это тренд».
Не хватает **ГЕЙТА widen-vs-close = подтверждение тренда.**

## Предложенный дизайн (черновой — твой вход улучшить)
Когда нога кровит на сильном ходе (ход > k×ATR за m баров), классифицируем ход:
- **НЕ подтверждён (отскок/чоп) → Stage-2 (расширить, держать).** Кандидат-признаки:
  BTC под EMA200·4ч / RANGE, vol LOW, спайк-и-откат.
- **ПОДТВЕРЖДён (тренд) → Stage-3 (закрыть ногу).** Кандидат-признаки (нужно неск.):
  BTC H5-флип + реклейм EMA200·4ч в сторону хода; vol-расширение держится; ход/ATR
  устойчив; альт пробил свой уровень с продолжением.

Сигналы, что у нас ЕСТЬ: BTC 4h H5 (EMA14/77/200), volatility_regime (LOW/HIGH),
ATR/move, idio_excess (DECORR alt vs BTC).

## Честные границы (согласованы)
Реактивно, не предсказание (стена чоп-vs-тренд). Расширить — дёшево/обратимо (доказано
на живых без рестарта). Закрыть — гейтится подтверждением, чтоб не резать рейнджера.
Semi-manual: пинг «расширь»/«закрой — тренд», оператор жмёт (авто-widen через GinArea
API не делаем — шрамы set_params).
