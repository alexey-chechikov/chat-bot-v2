## 4. Пять ворот CLAUDE.md — чек-лист, каждое «прошло / не прошло»
1. **Издержки** (gross, пока возврат не пришёл деньгами): мин. стоп = круг / 0.2. Тейкер+тейкер 0.096% → ≥0.48%,
   с проскальзыванием 0.136% → ≥0.68%; мейкер-вход + тейкер-выход 0.064% → ≥0.32%, с проскальзыванием на
   выходе ≥0.42% (только с моделью исполнения лимитки).
2. **Разрез по времени:** подбор на старой трети → проверка на средней → решение по свежей; свежая часть в плюсе
   сама. Для сеток вторая половина и с нуля, и непрерывно (снимок на границе — до событий минуты границы).
   Просмотренная половина — НЕ вне выборки: для неё нужен новый календарный период.
3. **Доверительный интервал без нуля**, n ≥ 100 разрешённых сделок.
4. **Плоская поверхность:** соседи по обе стороны нуля → шум; называть точный список соседей («5 точек: …»).
5. **Живое против бэктеста:** та же настройка бэктестом (копия frozen, обрезанная с первой записи
   `state/weex_grid*_journal.jsonl`) против живого журнала — тейки, оборот, закрыто — ДО того, как строить. Живых
   дней мало (BTC с 09.10, ETH с 11.10) → «не проверено», а не «прошло». `pnl_reconcile.py BTC|ETH` (учёт = биржа до
   цента) — только предпосылка, не сами ворота.

## 5. Отчёт по полному капиталу
Итог = закрыто − комиссии + мешок (+ фандинг); худшая просадка по минутным закрытиям; по сторонам; доля
депозита; совместная кривая, если стратегий несколько.

## 6. Контроли
- Режимный выключатель — контроль по ОТРЕЗКАМ: исходные границы фиксированы до случайного назначения; на КАЖДОЙ
  границе закрытие и сброс опорной цены, даже если случайная сторона совпала; плюс контроль с тем же временем в
  рынке (±1 п.п.); не меньше 999 повторов, ранг (k+1)/(n+1); перевёрнутое правило. Быстрый прогон с меньшим числом
  повторов — не контроль (при 12 повторах ранг не бывает меньше 1/13), выводов по нему не делать. Свой инструмент —
  `regime_grid.py SYM --ctl=999` (печатает ранг; часы счёта); ранги 0.23 / 0.12 в CLAUDE.md посчитаны GPT и локально
  на 999 не воспроизведены. Контроль «то же время в рынке ±1 п.п.» своим кодом пока не реализован → «не проверено».
  BTC и ETH — не независимые подтверждения. Контроль по дням врёт — дробит работу сетки.
- Сигналы входа: случайное направление в те же моменты; сдвиг по кругу; плацебо.

## 8. Решение
- Все пять ворот прошли → живьём малым размером (не долгий paper). Не прошло → «нет» с цифрой. Слабый контроль —
  одним числом во всех местах, с указанием варианта: «ранг 0.23 (BTC, лонг/шорт по режиму: 0.225 без фандинга /
  0.238 с фандингом; живой „только лонг“ — 0.466 BTC / 0.182 ETH с фандингом) — слабый, контроль не пройден».
- Размер: таблица «размер → итог / свежая половина / просадка / доля депозита»; эффективность = итог / просадка.
- Исполнить решение = дать оператору готовую команду (`/weex [eth] set ордер N потолок M`, `/weex … live|start`).
  `enabled`, `dry_run`, размер и включение живого меняет ТОЛЬКО оператор; Claude конфиги живых ботов не правит и
  ордера не ставит.
