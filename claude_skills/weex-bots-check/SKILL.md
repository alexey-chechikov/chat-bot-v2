# Проверка ботов WEEX — только чтение

Ничего не снимать, не перезапускать, конфиги не менять без слова оператора — даже найдя сироту или ошибку.
Ниже `x.py` = `/Users/alexeychechikov/code/bot7/.venv/bin/python3 /Users/alexeychechikov/code/bot7/research/weex/x.py`
(CWD сессии не bot7, переменные между вызовами не живут). Без `cd`, без `$(…)`; дату — литералом.

## Шаги (независимые — параллельно)
1. **Счёт, цикл, режим, ручные позиции:** `account_now.py` (код 0 — ок, 1 — проблема, 2 — не прочитано):
   - депозит, все позиции (средняя, PnL, фандинг);
   - жив ли цикл — учёт живой сетки старше 60 с = «есть проблема: сетка не ходит» (карточка, orphan_check и ошибки
     на мёртвом цикле выглядят чисто);
   - расстояние до SMA100 и порог сегодняшнего дневного закрытия UTC, ниже которого завтра лонги закроются по рынку;
   - сторона из `release_sides`: объём на бирже, ордера/algo/СДЕЛКИ бота после «передано оператору» (все 0).
   Объём ручной стороны сверить с прошлым значением (память `project_portfolio_now`); изменился — кто: `user_trades`
   → `order_info(orderId).clientOrderId` (`b7g…` — бот, UUID — оператор). Изменение не от оператора — «есть
   проблема» первой строкой; подтверждённое изменение оператора — обновить базу в памяти с датой и временем.
2. **Карточка:** `card_now.py` — сетки (режим, шаг/цель/ордер, лоты, мешок, закрыто), тренд, занято/общий потолок,
   фандинг по символу. Баланса нет.
3. **Ордера против учёта:** `orphan_check.py` — критерий «сирот 0 и лотов без тейка 0» (сопоставлено, неясные по
   cid, algo b7). Находка сразу после постановки/исполнения — перепроверить через 10–20 с.
4. **Сверка денег:** `pnl_reconcile.py BTC` и `pnl_reconcile.py ETH` — ИТОГ «совпадает» (деньги и комиссии ±$0.01,
   объём точно) по сторонам бота; по переданной стороне — «сделок бота после передачи 0». Живые шорт-сетки SB/SE
   (с 21.10, запуск кнопкой `/panel`) — ещё `pnl_reconcile.py SB` / `… SE`. SB ведёт BTCUSDT SHORT рядом с ручным
   шортом оператора: в `account_now` объём этой стороны — «в т.ч. лоты сеток», ручная часть = позиция − лоты SB;
   ордера/сделки SB на переданной стороне — не нарушение, любой другой сетки — ПРОБЛЕМА.
5. **Ошибки и предупреждения:** `errors_today.py [YYYY-MM-DD]` — ERROR с причиной (все errors.log*) и WARNING
   (launchd_app_runner.err). Разовые `Remote end closed connection` и `weex_book.reconnect` безвредны.
   `weex_grid.halt` / `weex_trend.halt` — первой строкой «есть проблема». Всегда разбирать (имена сверены с кодом
   12.10): weex_grid — `place_rejected`, `place_failed`, `place_no_id`, `orphan_order`, `external_close`,
   `flatten_send_failed`, `flatten_trades_failed`, `pending_not_found`, `pending_adopted`, `tp_qty_mismatch`,
   `stray_tp_unallocated`, `fee_unresolved`, `regime_failed` (режим неизвестен — входов нет); с 20.10 —
   `fee_incomplete` (ответ сделок на пределе 100, комиссия — нижняя оценка), `position_mismatch` (ERROR: лотов всех
   сеток больше позиции биржи 3 прохода — входы стороны остановлены; первой строкой «есть проблема»),
   `position_restored`, `position_audit_skipped` (сверка позиции не прочитана); weex_trend —
   `rejected`, `pending_not_found`, `cancel_algo_failed`. «ПОКРЫТИЕ НЕПОЛНОЕ» — сказать.
   Общая сверка позиции — `state/weex_position_audit.json`: `blocked: true` у стороны = входы стоят.
6. **Конфиги** (поля по файлам; `release_sides` только у BTC, `regime_sma` — у BTC и ETH):
   - `state/weex_grid_config.json` (BTC), `state/weex_grid_eth_config.json` — enabled, dry_run, sides,
     release_sides, regime_sma, step_pct, target_pct, order_qty, max_notional_usd, max_lots_per_side,
     daily_loss_stop_usd и stress_budget_frac (0 = выкл);
   - `state/weex_grid_xau_config.json` — золото, лонг+шорт 0.75/0.3, dry_run, без режима;
   - `state/weex_grid_sb_config.json` / `…_se_config.json` — заряженные шорт-сетки BTC/ETH без режима (выключены,
     пока оператор не запустит); `flatten_request` в любом конфиге — закрытие позиций бота по кнопке (снимается go);
   - `state/weex_portfolio_config.json` — enabled, gross_cap_usd;
   - `state/weex_trend_config.json` — enabled, dry_run, symbols, risk_usd, max_notional_usd.
7. **TradeGPT:** читать `state/tradegpt_signals.jsonl` скриптом-файлом (число, последний, уже посчитанные исходы).
   `tradegpt.summary()` НЕ вызывать: ходит в сеть и ПЕРЕЗАПИСЫВАЕТ журнал (гонка с записью нового сигнала); свежую
   сводку оператор получает сам — `/tgpt`.
8. **Запись стакана:** файлы `state/weex_book/` растут (mtime свежий) — отдельная задача, о цикле сеток не говорит.
9. **GinArea** — только если спросили: боты стоят с 07.10, движок — для бэктестов.

## Ответ оператору (коротко, его цифрами)
Первая строка — «всё работает» или «есть проблема: …» и депозит. Затем таблица по каждому живому боту: сторона,
шаг/цель, ордер в монете и ≈$, потолок, режим и запас до SMA100, лоты, мешок, закрыто. Ручные позиции оператора —
отдельной строкой (объём, средняя, PnL). Холостые — одной строкой. Занято / общий потолок, ошибки с причиной.
Ожидаемое (гонка сироты, безвредные разрывы) — одной фразой. Если что-то нужно менять — готовая команда `/weex …`
для оператора, не правка самому.
