# Daily context outcome repair v1 — implementation contract

18 October 2026. New research-only helpers; existing daily code, VERIFIED_FILES, archives, analysis reports, analyst notes, pilot journal, bots and orders remain unchanged. The implementation is submitted for independent reading review before activation. No real network collection under this new helper is part of this implementation task.

## Finite history and daily compatibility

One public collector invocation, at most six HTTP GET attempts, no retries/redirects/auth/proxies/WS: Binance clock; BTCUSDT spot and USD-M perpetual 15m klines; 15m OI; funding; optional premium. One fixed 96h history window (384 closed 15m bars, 385 OI endpoints), UTC-aligned and bounded by min(actual local time, server time); more than 96h absence remains missing. OI historical retention is limited; no unlimited promise. Failed clock means no dependent market request and explicit missing sources. Known clock skew is metadata, not provider lag.

Produce an immutable `history.json` with schema `coinglass-outcome-history-v1`, actual timestamps, original request/evidence hashes, extended sources, and a compatible legacy daily fragment `public_sources.json` retaining the original 96/97-point definitions and tail. Raw extended observations must not masquerade as a 96-point source. New history data have transport/request-window metadata separate from the legacy series definition. All inputs/outputs local; public prices can later be exported in a minimal aggregate for independent verification. Raw CoinGlass is never an input or output here.

Collector and evaluator agree on extended sources using the same id, market_scope, aggregation and url path as the old sources; normalized rows are the old public observation field names. Each extended source additionally carries an explicit `legacy_definition` (old semantic object with requested_closed_bars=96 / expected_points=97 and all other stable definitions exactly preserved). Evaluator verifies this definition against actual endpoint/id/product/units, does not blindly trust a supplied hash, and compares it to the frozen old analysis semantic object/hash. Compatibility is an allowlisted adapter, never by price similarity or matching symbol alone.

## Offline outcome supplements

Evaluator reads only explicitly selected existing local daily report, analysis report, analyst-note JSON and public history files; no account/config/raw evidence reads. Discover only expected directory/file names, reject symlink/junction/path escapes and malformed/future identities, bound JSON size. Note-provided absolute paths never authorize arbitrary reads. Resolve referenced analysis IDs within the expected analytics directory, verify its SHA where supplied. A legacy note without analysis_id can bind only to the unique analysis sharing its input_run; missing/ambiguous binding remains missing with reason.

Numerical analysis anchor: ceil(analysis.created_at_ms / 15m). Human-note anchor: ceil(max(note.created_at_ms, bound_analysis.created_at_ms) / 15m). Never evaluate text from an earlier machine anchor. Keep those records separate. Do not invent old hypotheses. Current note's structured `future_condition_plan` is descriptive context; unsupported/free-text conditions are explicitly not automatically assessed. Price paths are not a verdict on narrative or trade profit.

Horizons 15/60/240/1440m require exact fully closed 15m grids. PENDING before maturity or before a refresh could observe the endpoint; MISSING after suitable refresh with absent required rows; CONFLICT if any required timestamp has incompatible versions; MATURE only with every required row. Per-market return is raw close/open-1, not zone-oriented return or PnL. Spot/perpetual rows are separate. Flow context (volume, quote volume, trade delta, weighted F) requires its complete same interval; OI requires exact same anchor/end endpoints and units. Missing context is null independently of price availability. Never interpolate, forward-fill, substitute forming/trade-vs-mark prices or synthesize a missed CoinGlass snapshot.

All history revisions are immutable and contradictory timestamps remain excluded across the complete admitted history. Ignore data received after the actual evaluation time. Every supplement has actual creation time, input content hashes, code hash, its own immutable ID and local report/summary. Canonical input identity plus evaluated time-bucket/maturity state makes same-input repeats idempotent while permitting later maturity without a new daily run. New inputs or maturity produce a new supplement; old reports/notes/supplements are never rewritten. Concurrent writers must not overwrite a destination or leave a bogus successful result. No network function in evaluator. Daily overview names the immediately preceding human note by actual creation order; evaluates all older records separately.

Public independent-check export is opt-in and minimal: note/analysis opaque ID, anchor UTC, market, horizon, status, baseline open/end close/return and coverage/code/input hashes; no raw CoinGlass, narrative, screenshots, file paths, account data or orders. Its timestamps are actual export times, not invented earlier availability.

No real historical PnL or forecast score is calculated.

Deliver code, focused synthetic tests, README/activation commands, pinned SHA manifest and actual QA.
