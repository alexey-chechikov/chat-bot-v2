# CG-SR1 v0 — изолированный offline-прототип

Версия `CG-SR1-v0-offline-0.1`, 15.10.2026. Реализован кандидат из раздела 2C
`C:\bot7\research\weex_publish_20261010\docs\HEATMAP_NEXT_TESTS_2026-10-15.md`.
Это выполненный диагностический симулятор, **не результат проверки доходности**.
Код не читает старый journal, screenshots, snapshots или конфигурации; не содержит
сетевых запросов, сборщика, биржевого клиента, кода счёта или отправки ордеров.
Использован только Python standard library. Claude/Anthropic не используются.

## Запуск

Из этой папки, Python 3.10+:

```powershell
python -B -m unittest -v test_cg_sr1

# Этот генератор создаёт только явно выдуманные данные.
python -B make_synthetic_fixture.py --output-dir .\synthetic_fixture
python -B cg_sr1.py --metadata .\synthetic_fixture\metadata.synthetic.json --snapshots .\synthetic_fixture\snapshots.synthetic.json --prices .\synthetic_fixture\prices.synthetic.csv --output .\synthetic_example_report.json --synthetic
```

В поставленной папке эти синтетические файлы и результат уже сохранены. Генератор
и CLI отказываются перезаписывать существующие файлы: для нового прогона выбрать
новую папку/выходной путь. CLI требует все три входных пути и выходной путь явно.
Старые скрины и manual pilot не запускались как backtest.

Для реальной отдельной будущей серии убрать `--synthetic` и передать нормализованные
входы с `synthetic: false` в metadata и каждом snapshot. Точная допустимая серия:
`CG-model1-Binance-BTCUSDT-24h-ui085-forward-v2`. Pilot, reference, v1 и другие
идентификаторы отвергаются. Наличие этой строки и булевых флагов **не доказывает
prospective-происхождение**. Offline-код проверяет декларации и внутреннюю
согласованность входа; он не аудитор времени получения сайта, подписи снимка,
реальной свежести матрицы или истинности annotation lock. Подмена наклейки series
не превращает старые изображения в допустимые наблюдения.

## Чистый интерфейс

```python
from cg_sr1 import run_research
report = run_research(metadata_dict, normalized_snapshot_rows, closed_1m_rows,
                      synthetic=False)
```

`run_research` не делает I/O и не меняет переданные объекты. Результат пригоден для
JSON: точные десятичные величины представлены строками, UTC-время — integer ms.
CLI читает каждый входной файл один раз в bytes; парсинг JSON/CSV и SHA256
выполняются из этих же сохранённых байтов. Изменение исходного файла во время
расчёта не меняет хеш уже использованных данных. Это не атомарный снимок сразу
трёх файлов: caller должен передать согласованный набор; независимая верификация
provenance всё равно требуется. Содержимое исходных файлов не дописывается и
не исправляется.

## Нормализованные входы

Полные примеры схемы находятся в `synthetic_fixture`. Эти примеры выдуманы целиком,
включая цены, зоны, timestamps и tick/quantity step; они **не являются текущими
спецификациями Binance**.

Metadata JSON — объект с полями:

- `schema_version: cg-sr1-input-v0`, точный `series_id`,
  `collection_role: prospective-forward-v2`, явный boolean `synthetic`;
- `provider: CoinGlass`, `model: model1`, `exchange: Binance`, `symbol: BTCUSDT`,
  `instrument: perpetual`, `lookback: 24h`, `threshold: 0.85`;
- `price_source`: Binance/BTCUSDT/perpetual, `interval: 1m`, `timezone: UTC`,
  `closed_only: true`;
- `data_as_of_ms`: граница, к которой все переданные 1m-свечи уже закрыты;
- `atr_seed_start_ms`: заранее выбранное UTC15m-начало пути seed ATR;
- `contract`: положительные `tick_size`, `quantity_step`, `verified: true`,
  непустая `verification_source`, `verified_at_ms`. Это декларация проверенной
  спецификации от вызывающего кода. Прототип не получает спецификацию из сети.
  Объявленная проверка должна быть не позже входа и не позже data_as_of.

Snapshots JSON — массив записей. Для каждого `frozen`:

- уникальный immutable `snapshot_id`, точные `series_id`, `synthetic`, `slot_ms`;
- `slot_ms` — UTC 00/06/12/18; `capture_ms`, `annotation_lock_ms`;
- `status: frozen`, `source_record_complete`, `source_record_fresh`,
  `settings_match`, `annotation_frozen` — все явно `true` для допуска;
- положительный `frozen_spot`, `lower_zone: {low, high}` и `upper_zone: {low, high}`,
  с порядком `lower.low < lower.high < spot < upper.low < upper.high`.

Пропуск наблюдения — отдельная запись с id/series/synthetic/slot,
`status: missed` и непустым `reason`. Она остаётся в результате. Отсутствующие
слоты код не восстанавливает: полноту реестра попыток должен предоставить caller.
Некорректные источники/зоны/свежесть дают skip с причиной. Для слота берётся первый
допустимый freeze; одинаковое время разрешается snapshotID. Все остальные записи
сохраняются с `LATER_FREEZE_FOR_SLOT`. Freeze обязан попасть в [slot, slot+2min]
и быть не позже `data_as_of_ms`.

Prices CSV — строго столбцы `ts_ms,open,high,low,close` в таком порядке, с
уникальными возрастающими UTC minute-open ms. Цены положительные, конечные,
на объявленной tick-сетке, диапазон OHLC согласован. Пропуски допустимы как факт
неполных данных и приводят к censored/cancel, а не интерполяции. Дубли, неверный
порядок и незакрытые по data_as_of строки отвергают весь вход. Не передавать
секреты, счёт, личные fills или ключи.

## Реализованные правила

1. Effective freeze = max(capture, annotation lock). `t0` — первая минутная
   граница **строго после** freeze, даже если freeze ровно на минутной границе.
   Deadline всегда исходный `t0+240min`. v0 оценивает только зрелые эпизоды:
   до `data_as_of_ms >= deadline+1min` запись `PENDING/EPISODE_NOT_MATURE`, без
   поиска кандидата и без portfolio allocation. Closed-only CSV требует, чтобы
   deadline-минута закрылась. Нормальная незрелость не считается missing/censored;
   после границы зрелости фактические пробелы в необходимых данных — censored.
2. Только полные UTC15m из 15 последовательных 1m. Начало сигнала >= t0,
   закрытие и следующий 15m-open **строго раньше** deadline. LONG: low строго
   ниже lower.low, close строго выше lower.high; SHORT зеркально.
   Сначала проверяется касание обеих зон диапазоном анализируемой 15m-свечи:
   оно расходует снимок с отдельной причиной даже без подходящего reclaim.
   Первый reclaim-кандидат расходует снимок при любом дальнейшем отказе;
   повторного/отложенного входа или повторного входа после выхода нет.
3. Предыдущий ATR14 Wilder не включает сигнал: 14 TR с настоящим previous close
   требуют минимум **15 последовательных полных 15m-баров**. Первый ATR = mean
   14 TR, затем `(13*previousATR+TR)/14`. Путь начинается в явно заданном seed.
   Пробел на этом пути делает последующие ATR недоступными: тихой замены seed
   или продолжения через пробел нет. При длинной истории caller должен заранее
   выбрать и сохранить непрерывный seed path, а не подбирать его по результату.
4. `E` — raw open следующей UTC15m-свечи. S = low−0.1*previousATR для LONG,
   high+0.1*previousATR для SHORT; округляется **от цены**, вниз/вверх по tick.
   T = ближняя граница противоположной исходной зоны. Не переопределяется новой
   картой. Если цель не на tick-сетке, отказ; скрытого округления цели нет.
5. Проверяется направленная геометрия до модулей. `c=0.0008`,
   `(G-cE)/(D+cE) >= 2`, `q=floor_step(min(25/(D+cE), 10000/E))`.
   Фиксированный сравнительный капитал 10000 и бюджет 25, без compounding.
   Нулевой после округления q даёт отказ; cap notional и запас расходов
   проверяются Decimal-арифметикой.
6. Общая одна позиция. События входа сортируются по entry time, затем freeze,
   затем immutable id. Busy расходует кандидат без отложенного входа. При
   обычных 6h слотах и 4h horizon перекрытия не возникают; отдельно проверены
   конкурирующие внутренние synthetic candidates. Выход на известном open
   освобождает место на этом open; неизвестный intrabar-порядок — на следующей
   минутной границе. Censored исполнение блокирует будущую ёмкость портфеля
   как `PORTFOLIO_STATE_UNKNOWN`, а не создаёт фиктивный свободный счёт.
7. После входа известный 1m-open проверяется раньше неизвестного порядка high/low.
   Защитный stop-gap исполняется по **open** и может превысить плановый риск.
   **Консервативное допущение для limit target-gap: fill ограничен самой целью,
   без положительного улучшения до open**. Известный target-gap имеет приоритет
   над последующим минимумом/максимумом минуты. Если на open нет срабатывания,
   а SL и TP затронуты одной 1m, выбирается стоп. Обычное касание в модели
   исполняется по порогу. Начальная защита действует с момента entry open.
8. Выход ровно на 1m-open deadline, в том числе вне 15m-границы; экстремумы
   deadline-свечи не используются. На этом open сначала действует standing
   stop/target: stop-gap по open, target-gap по T без улучшения; только open
   между барьерами даёт `DEADLINE` по open. Отсутствует нужная минута — censored, цена
   позднего open не подставляется. Разрыв до возможного выхода также censored;
   последующее касание цели не восстанавливает неизвестный путь. Известный
   ранний выход не отменяется разрывом уже после него.
9. Два diagnostic ledgers 4/8bp содержат одинаковые входы, выходы и q, рассчитанное
   с запасом 8bp. `net = signed raw gross − rate*entry notional`. Запас 8bp не
   вычитается повторно; отдельные fee/funding/slippage не добавляются.

## Результат и границы

JSON содержит все переданные наблюдения, причины отказов и их отдельные счётчики,
сигнальные времена/ATR/геометрию/размер для кандидатов и ledgers 4/8bp. У неизвестного
исполнения gross/net = null, оно не считается нулевым результатом. Число closed,
censored, pending и entered выводится отдельно. Это диагностический fixed-size ledger,
а не equity replay с ликвидациями, margin, leverage или фактическим балансом.

**Идеализированная OHLC-модель не подтверждает maker fills.** Нет BBO, очереди,
partials, cancellation latency, реальных fees/funding, bid/ask, contract changes
или проверки доставки данных по фактическому received-at. Восстанавливается
каузальная временная схема свечей; реальное поступление данных и доступность
снимков не подтверждены. Источники должны быть предварительно нормализованы и
аудированы отдельно. Используются только цена и исходные зоны; spot filter,
OI/funding/flow-фильтры, UI/API-сбор и price-only control selector **не реализованы**.

Проверен только синтетический набор. Доходность CG-SR1 на будущей рыночной серии
не рассчитывалась и не установлена. Нужны отдельные допустимые forward-v2
наблюдения, независимая проверка provenance и последующий execution replay.
