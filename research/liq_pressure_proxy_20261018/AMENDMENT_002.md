# LPX-A0 amendment 002 — evidence gates and adapter semantics

Registered after initial synthetic implementation tests, before any real input, target loading, market calculation or statistical result. This amendment takes precedence over ambiguous gate/interpretation wording in the original protocol; it does not change the primary comparative score, model parameters or target-based selection.

1. The minimum eight UTC-week clusters and forty UTC days must contain defined scores: a qualifying day has at least one anchor with defined d, and a qualifying week at least one such day. Healthy-feed days/weeks with no observed messages remain counted and displayed separately, but do not inflate information gates or enter the score bootstrap as invented zero means. Bootstrap samples only qualifying weeks, with all their defined daily means; the denominator is therefore nonzero. Report calendar, feed-valid and score-defined counts separately. Other fixed gates remain unchanged.
2. The primary OI proxy versus price-only contrast tests the entire fixed construction, including OI-positive cohort birth timing AND OI masses. It does not isolate the effect of OI weights alone. A future weight-only claim would need its own same-births/equal-masses control registered before targets. Descriptive log-scores of each method versus uniform exposure should accompany the comparative score, without becoming new primary tests or a basis for selecting a method. This distinguishes an informative proxy from a comparator that simply performs poorly.
3. A Binance force-order adapter uses order time `o.T` as target event time, and preserves envelope `E` and any actual receive time separately. Message minutes are half-open `[anchor+k*60000, anchor+(k+1)*60000)`. MARK close is the close of that same minute; it can occur after the message within that minute. This is a retrospective temporal concentration score, not the price at the exact liquidation trigger.
4. Canonical identity for an archived force-order message requires known source schema and original public envelope fields, including E and the complete o object. A deterministic UTF-8 JSON serialization (sorted keys, no whitespace, preserved JSON numeric/string types, no local receive timestamp) receives SHA256; transport-identical repeats collapse, not messages merely sharing price/size/time. Exact schema/adapter SHA and normalization decisions must be in the inventory/RUN_PLAN. A normalized reference-kernel message can carry an adapter-supplied identity, but the kernel cannot certify provenance from that string alone. Unknown legacy identity/time/coverage means NOT_ASSESSABLE, not a guessed event or no-event.

The conditional estimand and all limitations remain: censored public messages, no full liquidation census, no price forecast, no PnL, no proof of CoinGlass equivalence, no authorization for Step B or deployment.
