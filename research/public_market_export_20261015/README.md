# Передать публичную запись WEEX с Mac одним архивом

Offline helper для Python 3.9+ из стандартной библиотеки. Он **не собирает данные**, не обращается к сети, не ставит ордера и не читает account/config/.env. Источники не изменяются. Запускать на Mac вручную; сам Mac из Windows не проверялся.

Указать существующую папку `state/weex_book` внутри своего checkout и явные UTC-даты. Пример, **заменить путь и даты на фактические**:

```sh
python3 export_public_market.py \
  --source /ABSOLUTE/PATH/chat-bot-v2/state/weex_book \
  --start-date 2026-10-13 --end-date 2026-10-14 \
  --outzip /ABSOLUTE/PATH/weex_public_20261013_20261014.zip
```

Выходная папка должна существовать; архив с таким именем не должен существовать. Скрипт не следует симлинкам, не обходит подпапки, не читает посторонние имена. Он принимает **только** точные имена:

```text
BTCUSDT_<YYYYMMDD>_depth.csv
BTCUSDT_<YYYYMMDD>_trades2.csv
BTCUSDT_<YYYYMMDD>_events.csv
ETHUSDT_<YYYYMMDD>_depth.csv
ETHUSDT_<YYYYMMDD>_trades2.csv
ETHUSDT_<YYYYMMDD>_events.csv
```

CSV сохраняются побайтно. Проверяются точные recorder-v2 заголовки без лишних столбцов, ширина всех строк, UTF-8 и присутствующие числовые timestamps. ZIP пишется потоково, весь архив/CSV в RAM не загружается. В `manifest.json` — SHA256/байты/число строк каждого CSV, UTC-границы наблюдаемых timestamps, sessions, отсутствующие имена и ограничения проверки. SHA256 готового ZIP выводится в терминал. Публикация готового ZIP — атомарная через hard link в той же папке на Mac/POSIX (на Windows — rename, который не заменяет существующий файл), без перезаписи; если файловая система этого не поддерживает, скрипт завершится ошибкой.

Если CSV изменяется между проверкой и упаковкой, скрипт завершится ошибкой, не опубликовав ZIP. Для простого первого экспорта предпочтительны уже закрытые UTC-дни. **Не останавливать recorder ради экспорта.** Если нужен сегодняшний день и файл изменяется — повторить в стабильный момент или предоставить отдельно замороженную публичную копию; этот helper не делает такую копию и не обещает общий одновременный cutoff нескольких файлов. Временный файл не является готовым результатом и убирается самим helper; исходные файлы не удаляются.

Отсутствующие имена перечисляются, а не подменяются пустыми CSV. В частности, отсутствие `events.csv` за день без session events само по себе не доказывает разрыв записи. Экспорт частичного набора допустим для диагностики и **не означает admission**.

## Что необходимо для следующего расчёта

Сохранить уже накопленные дни до ротации: recorder удаляет CSV старше 10 суток по mtime. Для каждого анализируемого интервала нужен **предшествующий snapshot и вся цепочка дельт**, включая предыдущие UTC-дни, если сессия началась раньше. Сам экспорт не доказывает U/u continuity, полноту trade stream, 15 реконструированных уровней, staleness или правильность clock offset. Следующий отдельный шаг — read-only preflight `--stale-ms 1000 --min-levels 15` и coverage/gap report.

Для ETH нужен полный причинный прогрев сигнала и весь 120-минутный хвост каждого сигнала. Несколько последовательных суток пригодны для проверки механики; это не доказательство положительного ожидания. Уже зафиксированный ETH-протокол задаёт перспективные 60 последовательных дней и минимум 60 допустимых сигналов, контроль расходов/стресса и CI; одно достижение этих чисел также не доказывает прибыль.

В recorder-v2 нет отдельного набора официальных полных OHLCV, mark/index/funding settlements и версионированных tick/step/minQty/minNotional. Их структура здесь не проверена: helper их **не включает** и отмечает отсутствие. Точный FIFO, send/ACK/cancel latency и реальные maker fees невозможно получить из публичных CSV. Общего receive sequence/monotonic и исходного frame type `tradeSnapshot` также нет: старый пакет нельзя задним числом сделать полной записью очереди. Применимы только явно ограниченные модели/границы.

Проверки без сети и реальных данных:

```sh
python3 -m unittest discover -s . -p 'test_export_public_market.py' -v
```
