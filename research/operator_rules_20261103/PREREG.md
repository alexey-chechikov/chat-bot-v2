# Правила оператора (канал / голубая линия) на BTC H1 и H4, лонг и шорт — перебор с честным отбором (03.11.2026)

Записано ДО запуска `sweep.py`. Оператор 03.11: «проверь возможные улучшения и напиши индикатор по моим правилам, который
открывается на часе в лонг и шорт… можешь прогнать потоком разные варианты и найти рабочие?». Исходные слова
(поручение GPT): лонг — возврат цены к низу канала, если мы над голубой линией; отбой от голубой и закрепление 1–3
свечами; тейк у вершины канала; стоп — закрепление под линией ~5 свечами или ход >1.5% (особенно одной свечой);
шорт — закрепление под голубой, фиксация у низа канала, перезаход у верха канала; горизонтальная голубая — особые
правила (сетки в две стороны, отмена при уходе ~3%). Индикатор `bot7_operator_rules_h1.pine` реализует ту же логику.

## Формализация (одинаково в Python и Pine)
- Бары H1 или H4 BTCUSDT Binance spot 2017-08 → 02.11.2026; голубая B = EMA200 по close — своего ТФ или H4 (для H1:
  последняя закрытая H4). Канал: hi/lo = max high / min low 30 предыдущих баров.
- ЛОНГ, сигнал на закрытии бара, вход open следующего:
  * подтверждение: N последних закрытий выше B (N = 1 / 2 / 3);
  * «канал»: в последних 5 барах low ≤ lo·1.0015 и close > lo; «отбой»: в последних 5 барах low ≤ B·1.0015;
    семейство — канал / отбой / любое;
  * сигнал — только при переходе условия из «нет» в «да»;
  * цель — hi сигнального бара (лимит, maker); если цель ближе 0.2% от цены входа — сигнал пропускается;
  * выход рынком на следующем open: K закрытий подряд ниже B (K = 3 / 5) или импульс против: тело бара ≤ −x% или
    close за 5 баров ≤ −x% (x = 1.5 / 3 / выкл);
  * предел удержания 20 / 40 баров / нет; флет-фильтр: не входить, если |B/B[5] − 1| ≤ 0.15% (вкл / выкл).
- ШОРТ — зеркально (high ≥ hi·0.9985 — «перезаход у верха канала», high ≥ B·0.9985 — касание голубой снизу, N
  закрытий ниже B, цель lo, выход по K закрытиям выше B или импульсу вверх).
- Одна позиция на сторону; лонг и шорт независимы (хедж-режим). Расходы: вход тейкер 0.048% + 0.02%, цель maker
  0.016%, рыночный выход 0.068%; фандинг Binance UM (лонг платит, шорт получает). Единица номинала на сделку.
- Сетка: 2 ТФ × 3 семейства × N 3 × K 2 × x 3 × удержание 3 × флет 2 × голубая 2 (только H1; на H4 одна) × 2 стороны
  = 1 944 варианта. Сетки «при горизонтальной голубой» здесь не перебираются: флет-правила по средним оператора
  проверены 02.11 (F1 −$509, ранг 0.84) — в индикаторе зона флета показывается.

## Отбор (ворота 2, 3, 4 CLAUDE.md)
Периоды: A 2018–2021 (подбор), B 2022–07.2024 (проверка), C 08.2024–02.11.2026 (решение).
1. По A: варианты с n_A ≥ 20; 20 лучших по сумме net за A для каждой стороны.
2. По B: из них остаются с суммой B > 0 и n_B ≥ 15.
3. По C: «рабочий» — сумма C > 0 при n_C ≥ 15; затем для каждого рабочего: (а) контроль — случайный вход в моменты,
   где выполнено условие стороны (close по нужную сторону B, флет как у варианта), те же правила выхода, 999 повторов,
   ранг среднего net за C ≤ 0.05 и за всё ≤ 0.05; (б) ДИ среднего net за всё исключает 0 (n ≥ 100); (в) соседи —
   каждый параметр на шаг в обе стороны — все в плюсе в B и C.
4. Отдельно — устойчивость семейства: доля вариантов с плюсом в C среди плюсовых в A и B против доли среди всех.
   Если не выше — отбор по прошлому ничего не говорит о будущем.
Если ни один вариант не проходит п.3 — ответ «рабочих нет» с числами; параметры не подбираются заново после C.

## Дописано до запуска `r2_operator.py` (оператор 03.11: «тут есть улучшение по волатильности?»)
Размер по волатильности (как R2 в 432): вес сделки = медиана ATR14% за предыдущий год своего ТФ / ATR14% на сигнале,
0.5–2. Применяется без изменения входов и выходов к трём наборам: настройки индикатора по умолчанию на H1 (лонг и шорт:
«любое», N 2, K 5, импульс 1.5%, без предела, голубая своего ТФ, без флет-фильтра) и шорт-кандидат H4 (§ отбор).
Критерий: итог/просадка (переоценка по закрытиям бара) лучше без веса в A, B и C.
