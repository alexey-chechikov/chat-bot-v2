# Frozen offline daily analytics definitions

Version `daily-context-analytics-v1`, 16 October 2026. Only explicit `--local-root` immutable `YYYY-MM-DD/run_<actualms>/report.json` files with schema `daily-as-seen-v1` and `synthetic:false` are eligible. Preflight/synthetic trees and raw evidence are not read. The latest eligible real run is analyzed; an existing analysis for the same input run is reused, not rewritten. A changed SHA for an already analyzed immutable input is an error.

Analysis creation uses actual local UTC milliseconds at invocation. No historical timestamp CLI option exists. Synthetic tests can inject a clock only with the private synthetic-test flag, and their outputs remain explicitly synthetic. All new writes are below `local/analytics/analysis_<actualms>/`; prior archive/analysis files are never changed.

BTC spot and perpetual remain separate. Complete 24-hour metrics require exactly 96 unique, contiguous, explicitly closed 15-minute bars on the declared start/end grid. OHLC, volume and taker amounts are independently validated; reported F/delta are recomputed. Returns use first open to final close: 24h=96 bars, 1h=last4, 4h=last16. Base/quote volume and buy/sell/delta are separate. Volume-weighted F = sum(2*taker_buy_base-base_volume)/sum(base_volume), not mean(bar F). A zero denominator returns null. No incomplete 24h window is relabeled complete.

OI quantity and provider-reported value changes have separate provider units. Their start/end timestamps are checked against the perpetual bar window; no directional position inference follows from OI. Funding uses only individually observed signed events and their exact timestamps, with no assumed settlement interval, annualization or hypothetical position cash flow.

Comparisons use the immediately preceding real archive, matching source ID, canonical URL path, market scope, aggregation, explicit stable settings, metric definition and unit. Request/validation details and capture/window timestamps are not semantic definitions. Missing values or changed semantics produce null differences. Relative difference=(current-previous)/previous; previous zero gives null. Nested liquidation windows are separate metrics and are not added together. No matrix/zone values are reconstructed from images or null data.

Prospective observations freeze an anchor at ceil(actual analysis creation/15m)*15m, the first full bar starting at or after creation. The baseline is that bar's actual open. Horizons are 15/60/240/1440 minutes from the anchor. A horizon requires every exact closed bar in its grid; endpoint prices alone are insufficient. Return/high/low excursions are descriptive market outcomes, not trade entries, forecasts, markout PnL or permission.

Each MATURE price outcome also records aligned spot/perpetual volume, taker delta and weighted F over that same anchor-to-target grid, plus OI quantity/value changes at its exact endpoints. Source definitions are frozen to the earlier analysis. Missing aligned context remains null with an explicit reason; a valid price outcome is not invalidated by unavailable additional context. Daily current-window changes are stored separately and are not substituted for these same-window observations. Short 1h/4h flow and adjacent equal-duration volume comparisons, plus four hourly blocks within the current last4h, describe changing activity without causal claims.

Current and archived normalized rows can jointly cover the exact grid, but only under the same semantic definition. Conflicting overlap bars are excluded and reported. Before actual time reaches the target, status is PENDING. After time passes but without a newer actual archive collected at least 15 minutes after the target, incomplete coverage remains PENDING awaiting refresh. With such a newer refresh, absent/failed/incompatible data or grid gaps give MISSING even when the latest available bar is stale; it must not remain pending forever. Exact full coverage after actual target time gives MATURE. The JSON separates horizon elapsed, refreshed after target, and complete coverage. Each later analysis records a new evaluation of earlier frozen anchors plus related indicator changes, without rewriting old files or claiming causality. With once-daily 96-bar exports, some full 24-hour prospective windows may remain pending or eventually have missing coverage; no extra collection or backfill is triggered.

No network, browser, account/key/config reads, old journal writes, bots, orders, predictions, primary/shadow labels or automatic trading permission. `order_permission=false` in every output.
