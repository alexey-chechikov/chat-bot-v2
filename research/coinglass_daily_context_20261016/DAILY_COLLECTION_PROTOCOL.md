# Ежедневный контекст CoinGlass

Версия 2, 16.10.2026. Пользователь разрешил один конечный сбор в сутки в этом чате и затем попросил ежедневную видимую аналитику изменений и последующих движений. Плановое время: 17:00 Europe/Warsaw. Это отдельная серия `daily-as-seen-v1`; основной сбор рынка остаётся на Mac. Формат анализа и проверок — в ANALYTICS_PROTOCOL.md.

## Назначение и границы

Сохранять исходную картину, настройки, время чтения и доступные публичные числа для последующего исследования. Один суточный снимок не восстанавливает внутридневную историю карты, очередь заявок или поток сделок. Сам по себе он не разрешает входы, не даёт прогнозных вероятностей и не доказывает прибыльность.

Не менять ботов, ордера, конфиги, правила допуска CG-SR1 и старые зоны. Не добавлять наблюдения в `liquidation_heatmap_20261015/local/journal.sqlite`. Старую автоматизацию `coinglass` оставить отдельной досверкой пилота. Не обращаться к Mac, ключам, данным торгового счёта, Claude или ресурсам Anthropic. Не создавать Windows-службы, процессы в фоне, WebSocket-клиенты или непрерывные сборщики. Обычная временная вкладка сайта допустима только на время чтения; закрыть созданные вкладки после сохранения.

CoinGlass и Binance REST — разные источники, с разным охватом. Не называть Binance-only дельту агрегированным CoinGlass CVD. Дельта стакана не равна дельте сделок. Карта лимитных заявок не равна модельной карте ликвидаций. Производные Max Pain по ликвидациям и Deribit options Max Pain не смешивать. Периоды 1/4/12/24h вложены: их нельзя складывать.

Остальные присланные экраны полезны как справочник доступных признаков: ratios аккаунтов/позиций, киты, общий суточный объём, Max Pain по экспирациям и derived net positions. В первую ежедневную серию они не включены: сначала проверяется добавочная ценность ограниченного набора. Множество похожих агрегатов не считается независимыми подтверждениями. Присланные ранее изображения остаются исследовательским контекстом с исходным временем; задним числом наблюдения из них не создаются.

## Один запуск

1. Прочитать этот протокол и README. Проверить `local/YYYY-MM-DD/run_*/report.json` за фактическую дату Варшавы. Если уже есть реальный завершённый пакет за день, не собирать второй автоматически. Пропущенные дни не заполнять задним числом.
   Перед запуском Python helpers сверить SHA256 исходников с `VERIFIED_FILES.json`. Если проверенный файл изменён или манифест отсутствует, сетевой helper не запускать; сохранить причину и сообщить о необходимости проверки кода.
2. Получить фактические UTC milliseconds. Создать уникальную папку `local/preflight_<actualms>/evidence`. Начало и окончание чтения сохранять фактически. Имена файлов внутри evidence фиксированы по ID, без перезаписи.
3. Через разрешённый browser tool открыть максимум четыре страницы из таблицы. Проверить загрузку и выбранные настройки на экране. Допустима одна повторная проверка после загрузки; CAPTCHA, требование входа/подписки, отсутствие данных или недоступность браузера — источник MISSING/FAILED, без обхода ограничений. Не создавать подписки и не искать секретные endpoints.
4. Для доступной страницы сохранить документированным screenshot API JPEG и DOM-текст в evidence. Допустима обычная файловая запись возвращённых screenshot bytes; все действия с браузером — только browser tool. Зафиксировать время каждого чтения в settings.captured_at_ms. Не делать выводы о точных USD по цветам пикселей. Не считать время последнего рыночного события временем публикации карты. Если timezone/публикация неизвестны: event_asof_ms=null, lag_status=unknown, provider_lag_ms=null.
5. Запустить один конечный `fetch_public_context.py` установленным Python с явным --outdir в текущей preflight-папке. Не более шести публичных GET, без циклических повторов/живого потока. Сначала выполнить локальные тесты после изменения кода; при неизменном проверенном коде повторять их каждый день не требуется.
6. Собрать `daily_input.json`: schema=daily-as-seen-v1, timezone=Europe/Warsaw, synthetic=false, фактические collected_at_ms/finished_at_ms, четыре CoinGlass sources и полученные Binance sources. Все evidence paths относительны input-папке и начинаются `evidence/`. Недоступные значения null, никогда не ноль. Сохранять ошибки и флаги частичного покрытия.
7. Архивировать: `C:\Users\Kemper\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe -X utf8 -B C:\bot7\research\coinglass_daily_context_20261016\archive_daily.py --input <actual-preflight>\daily_input.json --outroot C:\bot7\research\coinglass_daily_context_20261016\local`. Проверить созданный report.json и наличие evidence/hash. Архивы неизменяемы; исправления — отдельный явно помеченный запуск, если потребовались пользователю.
8. Закрыть созданные вкладки. Оригиналы снимков, DOM, сырых данных и файлов отчётов остаются локальными. Не публиковать и не отправлять их другим сервисам или чатам. Краткий аналитический вывод в текущем чате прямо запрошен пользователем и разрешён.
9. Запустить проверенный offline analytics_daily.py по local-root, проверить расчёты и подготовить видимый аналитический обзор по ANALYTICS_PROTOCOL.md. Наличие сегодняшнего пакета отменяет повторный сбор, но не отменяет ещё не сделанную аналитику и её доставку.

## Качество и повторные сообщения

Сравнивать доступность источников, покрытие закрытых свечей, неизвестную задержку и изменения настроек с предыдущим реальным пакетом. Ежедневный аналитический отчёт теперь запрошен явно: его нужно показывать один раз в сутки, даже если вывод — «существенных изменений нет». Изменение цены описывается как факт, без автоматического вывода о найденном преимуществе. Сохранять компактный `local/daily_notification_state.json` с датой последней проверки, последним run и ключами уже сообщённых проблем, а доставку аналитики — отдельно в `local/daily_analysis_delivery_state.json`. Одинаковые нерешённые проблемы не сообщать повторно. После восстановления источника отметить восстановление. При первом запуске известные ограничения (неизвестная задержка сайта, недоступная матрица, текущий бар на JPEG) считаются исходным состоянием качества.

Работа расписания зависит от доступности локального хоста, приложения, сети и browser tool. Пропуск выполнения не равен успешному сбору. Не требовать включать Windows ради основного сбора на Mac. Новый суточный архив не присоединять к основной шестичасовой выборке или старому ручному пилоту.
